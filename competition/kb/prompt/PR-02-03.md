# PR-02-03 기능 카드로 작업 재사용하기
## 한 번 정리해 여러 번 쓰는 기능 카드

발표 자료를 만들 때마다 같은 방식으로 내용을 요약하고 확인 질문을 만드는 상황을 떠올려 보세요. 매번 순서를 처음부터 설명하면 시간이 들고, 중요한 단계를 빠뜨릴 수도 있어요. 이럴 때 작업에 필요한 안내를 묶어 두면 다음에도 꺼내 쓸 수 있어요.

이 과정에서 기능 카드는 특정 작업에 필요한 지침과 자료를 폴더 하나에 묶은 기능 모듈이에요. 필요하다면 실행 코드도 함께 담아요. 터미널에서 실행하는 코딩 에이전트 HelpyCode가 카드를 활용하면 반복해서 설명할 내용을 줄이고, 특정 작업에 맞는 순서를 따르도록 도울 수 있어요. 예를 들어 발표 요약용 카드와 질문 만들기용 카드를 차례로 활용해 하나의 작업을 구성할 수도 있어요.

다만 카드를 쓴다고 해서 요청을 해석하거나 결과를 확인할 필요가 없어지는 것은 아니에요. 같은 카드라도 주제와 대상에 따라 필요한 결과가 달라져요. 만든 요약이 원래 내용을 왜곡하지 않았는지, 질문이 발표 주제에 맞는지는 사용자가 살펴봐야 해요.

## 사용할 카드를 알려 주기

사용자는 요청할 때 기능 카드의 이름을 적어 사용을 명시적으로 지정할 수 있어요. 예를 들어 “HelpyCode, summary-note 기능 카드를 사용해 이 발표 자료를 요약해 줘”라고 요청할 수 있어요. 여기에 발표 대상과 원하는 요약의 길이까지 덧붙이면 이번 작업에 필요한 조건도 전달할 수 있어요.

HelpyCode가 요청과 관련된 기능 카드를 탐색해 활용할 수도 있어요. 하지만 원하는 카드가 분명하다면 이름을 직접 밝혀 주세요. 작업이 끝난 뒤에는 카드의 안내가 이번 요청에 적합했는지와 결과가 요구한 형식에 맞는지도 확인해요.

## 폴더와 CARD.md 살펴보기

이 과정에서 각 기능 카드는 독립된 폴더를 사용하고 그 안에 CARD.md를 둬요. CARD.md는 카드의 기본 정보와 작업 지침을 담은 문서예요. 필요한 자료를 모두 한 문서에 밀어 넣을 필요는 없어요. 역할에 따라 다음과 같이 나누면 찾고 고치기 쉬워요.

(표: PR-02-03-table1.csv)

scripts, references, assets 폴더는 필요할 때 추가해요. 예를 들어 요약 형식만 안내한다면 CARD.md만으로 시작할 수 있어요. 참고할 문서가 많아지면 references 폴더에 따로 정리해 두고, 지침에서 어떤 자료를 살펴볼지 설명할 수 있어요.

CARD.md의 맨 앞에는 YAML 형식의 기본 정보 영역을 쓰고, 그 아래에는 마크다운으로 작업 지침을 적어요. 기본 정보의 name은 카드를 구별하는 이름이고, description은 카드가 무엇을 하며 언제 쓰이는지 설명해요. description은 HelpyCode가 관련 카드를 판단하는 데 도움이 되므로 “요약하기”처럼 짧게만 쓰기보다 사용할 상황을 함께 적는 것이 좋아요.

```yaml
---
name: summary-note
description: 발표 자료의 핵심 내용을 짧게 정리할 때 사용해요.
---
```

위 기본 정보 아래에는 핵심 내용을 고르는 기준과 결과를 점검하는 순서 등을 적을 수 있어요. 지침은 다른 사람이 읽어도 따라 할 수 있도록 구체적으로 써요.

## 이름을 정하고 점검하기

이 과정에서 기능 카드의 이름은 영어 소문자와 하이픈(-)으로만 짓고 30자를 넘지 않아요. 이름의 처음과 끝에는 하이픈을 쓰지 않아요. CARD.md의 name은 그 기능 카드 폴더의 이름과 같아야 해요. 따라서 summary-note는 사용할 수 있지만, Summary-note는 대문자가 있고 summary-는 끝에 하이픈이 있어 사용할 수 없어요. summary2도 숫자가 들어 있어 사용할 수 없어요.

카드를 저장하기 전에는 이름과 폴더 이름이 같은지, description만 읽어도 쓸 상황을 알 수 있는지 살펴보세요. 지침을 고친 뒤에는 짧은 예시 작업으로 시험하고 결과를 확인해요. 이렇게 다듬은 카드는 다음 작업에서도 다시 꺼내 쓸 수 있어요.

## 용어 정리

- **기능 카드**: 특정 작업의 지침과 필요한 자료를 폴더에 묶은 기능 모듈이에요.
- **명시적 호출**: 요청에서 사용할 기능 카드의 이름을 직접 지정하는 것이에요.
- **기본 정보 영역**: CARD.md의 맨 앞에서 카드의 이름과 설명을 알려 주는 부분이에요.
