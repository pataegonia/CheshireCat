# PR-03-04 여러 파일 작업·설계 모드·되감기 지점
## 여러 파일을 함께 살펴보기

프로그램의 한 기능은 여러 파일에 나뉘어 있을 수 있어요. 화면에서 받은 정보를 다른 파일이 처리하고, 또 다른 파일이 결과를 검사하는 식이에요. 따라서 한 파일만 고치면 연결된 다른 부분에서 문제가 생길 수 있어요. 여러 파일의 관계를 함께 살피고 수정하는 작업을 멀티파일 작업이라고 해요.

이 과정의 실습 프로젝트는 함께쓰는 독서노트예요. 책을 기록할 때 나타나는 화면과 기록 처리, 결과 확인이 아래처럼 나뉘어 있다고 생각해 보세요.

(표: PR-03-04-table1.csv)

이 과정의 코딩 에이전트 HelpyCode는 터미널에서 실행해요. 작업 폴더를 살펴보도록 요청하면 파일을 하나씩 올리지 않아도 관련 파일과 연결 관계를 찾는 데 도움을 받을 수 있어요. 다만 실제로 무엇을 읽고 실행했는지는 결과를 보고 확인해야 해요.

## 찾고, 계획하고, 허락하기

에이전틱 검색은 에이전트가 검색어를 세워 파일을 찾고, 결과를 바탕으로 부족한 내용을 다시 검색하는 방식이에요. 예를 들어 제목이 저장되지 않는 문제를 조사할 때 화면의 입력 부분을 찾은 뒤, 그 값이 어디로 전달되는지 추가로 찾아볼 수 있어요. 한 번 검색한 결과만 보고 원인을 짐작하는 것보다 연결 관계를 살피기 좋아요.

이 과정의 설계 모드에서는 파일을 읽기 전용으로 살피고 수정 계획을 세우며, 파일을 직접 고치지 않아요. 그래서 여러 파일을 바꾸기 전에 수정할 파일과 순서, 확인 방법을 검토하기 좋아요. 계획이 그럴듯해 보여도 실제 원인과 맞는지는 사람이 확인해야 해요.

이 실습의 일반 모드에서는 파일을 수정하기 전에 사용자의 승인을 받아요. 이 실습의 자동 승인 모드에서는 파일 수정 승인 요청을 자동으로 받아들이지만, 중요한 명령 실행은 별도로 승인을 받아요. 자동 승인은 믿을 수 있는 작업에서만 신중하게 사용해요. 모드를 바꾸기 전에는 무엇을 허락하는지 확인하고, 원하지 않는 수정이 있으면 멈춰 달라고 요청해요.

## 큰 수정과 분기 실험

대규모 리팩토링은 프로그램의 기능을 유지하면서 여러 파일의 코드 구조를 정리하는 작업이에요. 파일 사이의 연결도 달라질 수 있으므로 작은 단계로 나누고, 단계마다 결과를 확인해야 해요. 먼저 설계 모드에서 계획을 받은 뒤 수정 범위가 알맞은지 살펴보세요.

이 과정에서는 `/clone` 명령으로 현재 대화 세션을 복제해 다른 방법을 분기 실험해요. 예를 들어 기존 기록 처리 방식을 유지하는 계획과 새 방식으로 정리하는 계획을 각각 검토할 수 있어요. 대화 분기는 파일 복사본과 같지 않아요. 같은 작업 폴더를 사용하면 한 분기의 파일 수정이 다른 분기에도 보일 수 있으니, 실험 전에 별도의 파일 복사본을 준비하고 작업 위치를 확인해요.

## 되감기 지점과 실습

HelpyCode는 파일을 고칠 때마다 되감기 지점을 자동으로 만들고, 되감기 지점은 최근 10개까지 남겨요. 되감기 지점은 수정 전 상태로 돌아가는 데 도움을 주는 안전장치예요. 다만 오래된 지점은 남지 않을 수 있고, 모든 외부 자료까지 보관하는 별도 백업을 대신하지는 않아요. 중요한 파일은 작업 전에 따로 복사해 두세요.

수정이 잘못되었다면 ESC 키를 두 번 눌러 되돌리기 화면을 확인하거나 HelpyCode에 방금 작업을 취소해 달라고 요청할 수 있어요. 돌아갈 지점과 적용 범위를 확인한 뒤 실행하고, 파일 내용과 실행 결과를 다시 살펴봐요. 취소 요청만으로 모든 변경이 복구되었다고 가정하지 않는 것이 중요해요.

이제 독서노트에서 제목을 입력해도 기록이 보이지 않는 상황을 연습해 보세요. 먼저 설계 모드에서 “제목이 기록되지 않는 원인을 찾고, 수정할 파일과 확인 방법을 계획해 줘”라고 요청해요. HelpyCode가 찾은 연결 관계를 검토한 뒤 일반 모드에서 필요한 수정만 승인해요. 마지막으로 제목을 입력했을 때 기록이 나타나는지와 기존 기록 확인 기능이 여전히 동작하는지 검사해요. 결과가 예상과 다르면 변경 내용을 살펴보고 필요한 경우 되돌린 뒤 다시 계획해요.
