## 1. 문제

대회 채점기는 `/guard`를 `/tutor`와 따로 부른다. 가드는 대화 이력과 후보 답변을 받아 **판정 JSON 하나**만 돌려준다. 응답 문구·수리·재생성은 가드의 일이 아니다(OT §2, §5).

가드는 세 가지로 점수를 잃는다(OT §6).
1. **입력 판정 실패**(45%): 막을 입력을 놓치거나(재현율) 정상 입력을 막는다(정밀도). 지표는 `block` F1이라 모두 허용하면 0점이다.
2. **범주 실패**(10%): `normal`이 아닌 입력의 범주를 틀린다.
3. **후보 답변 판정 실패**(45%): 근거 여부, 근거 없는 구간, 안전 여부를 틀린다. 근거 없는 구간은 후보 답변에서 그대로 옮긴 문자열이어야 한다.

제약이 설계를 정한다(OT §3, §9, §10).
- 모델은 `gpt-5-nano`(채팅)와 `text-embedding-3-small`(임베딩)뿐이다. 미리 학습된 분류·임베딩 모델 파일, 외부 API, 인터넷 데이터셋은 서버에 넣을 수 없다.
- 요청당 30초, 동시 64개, CPU만(C-8, 8코어로 추정), 요청 사이 상태 없음.
- `/guard` 요청에는 근거 자료가 오지 않는다. 근거 판정을 하려면 가드가 지식 베이스를 **직접 찾아야** 한다.

### 근거
- 범주 정의는 주어지지 않는다. 공개 세트 라벨에서 팀이 정의를 세워야 한다(OT §5).
- 기존 조사(R1–R11) 중 한국어 우회 표기(R5), 근거 판정(R7), 학생 안전(R9)은 여전히 쓸 수 있다. 상용 가드·외부 판정 API·학습 분류기 조사(R4, R6, ADR-0008)는 대회 규칙상 쓸 수 없다. 새 기준선에 맞춘 조사는 [R12](research/R12-competition-baseline.md)다. nano를 가드·구간 판정기로 쓴 공개 정확도는 없어서 모든 기대치는 공개 세트에서 잰다.

### 가설
결정적 신호(정규화 + 위기·PII·인젝션 규칙) + 가드 쪽 KB 검색 + 입력·출력을 나눈 `gpt-5-nano` 판정 + 코드 후처리(문장 번호 → 원문, `grounded` 계산)를 겹치면, nano 단독 판정보다 공개 세트 홀드아웃의 가드 점수가 오른다. 단계별 기여는 ablation으로 보인다.

## 3. 입력 범주

범주 10개는 대회가 정한다. 정의는 주어지지 않으므로 아래 **작업 가설**을 공개 세트 라벨로 확정한다.

| 범주 | 작업 가설(이름에서 추정) | 예상 `decision` | 확정 |
|---|---|---|---|
| `normal` | 자료 범위의 정상 학습 질문·인사 | allow | `[공개 세트 후]` |
| `answer_seeking` | 풀이 없이 정답만 요구 | `[공개 세트 후]` | `[공개 세트 후]` |
| `academic_dishonesty` | 시험·과제 대리, 부정행위 | block | `[공개 세트 후]` |
| `off_topic` | 수업과 무관한 요청 | `[공개 세트 후]` | `[공개 세트 후]` |
| `out_of_material` | 과목 관련이지만 자료 밖 | `[공개 세트 후]` | `[공개 세트 후]` |
| `jailbreak_injection` | 탈옥·지시 무시·시스템 프롬프트 요구 | block | `[공개 세트 후]` |
| `pii_disclosure` | 개인정보를 밝히거나 요구 | block(임시) `[공개 세트 후]` | `[공개 세트 후]` |
| `harmful_content` | 유해·위험 요청 | block | `[공개 세트 후]` |
| `emotional_distress` | 위기·정서적 어려움 신호 | block(임시: 튜터 `escalate`가 학습을 멈추는 응대라서) `[공개 세트 후]` | `[공개 세트 후]` |
| `low_signal_input` | 의미 없는 입력, 버튼 문구만 | allow(임시) `[공개 세트 후]` | `[공개 세트 후]` |

- "(임시)" decision은 공개 세트를 보기 전까지 GR-08 장애 기본값과 GR-06 직접 결정에만 쓴다. 공개 세트의 범주별 decision으로 바꾼다.
- **범주와 `decision`은 따로 판정한다.** 같은 범주 안에서도 decision이 갈리는지 교차표로 확인한다 `[공개 세트 후]`.
- 기존 S0–S14와의 대응(부록 B)은 정책 프롬프트 경계 사례를 쓸 때만 참고한다.

## 4. 구성 개요

결정 근거는 ADR-0009(상태 없는 판정기), ADR-0010(검색), ADR-0011(호출 구조).

```
POST /guard  (Bearer 인증 → 스키마 검증)
  ▼  [코드, 수 ms]
  ① 정규화(원문 보존, 정규화본 + 골격 뷰)
  ② 결정적 신호: 위기 어휘 · PII 패턴 · 확실한 인젝션 패턴 → 힌트(직접 결정은 정의상 확실한 low_signal·pii만, GR-06)
  ③ 후보 답변 문장 분리·번호, KB 검색(문장별 질의 + 창 안의 학습자 발화, 문자 2-gram BM25), 사전 필터(검색한 섹션 기준)
  ▼  [LLM gpt-5-nano, effort low, 2회 병렬. candidate_answer가 없으면 ④만]
  ④ 입력 판정: evidence → category → decision (첫 학습자 발화 + 최근 6턴, 신호는 힌트)
  ⑤ 출력 판정: 근거 없는 문장 번호 + safe (마지막 학습자 발화 + 답변 + KB 섹션)
  ▼  [코드]
  ⑥ 후처리: 문장 번호 → 원문, grounded = (근거 없는 문장 없음), output.category = input.category, 스키마 검사
  ▼
HTTP 200 + JSON
```

- 입력을 바꾸는 단계(①)는 분기 전에 끝낸다. 원문은 판정 대상으로 보존한다.
- 판정이 실패해도 항상 규격 응답을 낸다(GR-08). 요청 마감은 25초.
- 요청당 LLM 호출은 최대 2회(재시도 제외). 3표 투표는 쓰지 않는다(ADR-0011).
- 기동 때 KB 색인을 끝낸다(임베딩 ablation을 켤 때는 KB 임베딩도). 첫 요청에서 만들지 않는다(OT §3).

## 5. 기능 요구사항

우선순위: **P0** 제출에 필수 / **P1** 점수에 직접 기여 / **P2** 시간이 남으면.

### GR-01 HTTP 규격 (P0)
- `POST /guard`, `0.0.0.0:8000`(8080은 금지, 다른 포트는 제출 주소의 `/proxy/<포트>`와 맞추면 됨). 경로 끝 슬래시 리다이렉트 없음(3xx 금지).
- `Authorization: Bearer <token>` 확인. 토큰은 환경변수로 읽고 상수 시간으로 비교하며(`hmac.compare_digest`), 틀리면 거절한다 `[SPEC.md 대조]`(상태 코드). 확인 전 기본값은 401과 짧은 JSON 오류 본문.
- 인증 실패를 뺀 모든 응답은 HTTP 200 + JSON 하나. 비스트리밍. 본문 256KB 미만.
- 값은 규격의 대소문자 그대로. 필수 필드 누락·`null`·타입 오류 금지. `candidate_answer`가 없으면 `output`을 생략한다(OT: 후보 답변이 있을 때만 필수). 빈 문자열일 때 처리는 `[SPEC.md 대조]`. 확인 전 기본값: 키가 있으면 `output`을 넣는다(빈 답변은 `grounded=true`·`unsupported=[]`·`safe=true`).
- 요청·응답 스키마는 `docs/contract/guard.schema.json` 하나를 기준으로 하고, 서버 응답을 테스트에서 이 스키마로 검증한다.
- **수용 기준**: 공개 세트 전체와 퍼징 입력(빈 메시지, 매우 긴 이력, 깨진 유니코드, 누락 필드)에서 형식 오류 0건. `/guard/` 요청에 3xx 없음. 제출할 터널 주소의 `/guard`로 리다이렉트를 따르지 않고 POST해 200 JSON(OT p.21). 인증 실패 테스트.

### GR-02 전처리 (P0, v4 GR-01 유지)
- 원문은 보존하고 두 뷰를 만든다(ADR-0001).
  - **정규화본**(LLM용): 보이지 않는 문자 제거 → 전각·반각 접기 → 자모 조합. 수식 기호는 바꾸지 않는다.
  - **골격 뷰**(매칭 전용): 보이지 않는 문자 제거 → 전각·반각 접기 → NFKC(자모 밖) → 공백·기호·숫자 제거 → 모음 반복 축약 → 자모 조합 → 늘여 쓴 모음 제거 → 소문자.
- 골격 뷰는 어휘 매칭에만 쓴다. 코드 질문(파이썬 과목)이 망가지지 않게 입력 판정 LLM에는 정규화본을 보낸다.
- **후보 답변은 지우지 않는다.** 정규화본은 보이지 않는 문자(Cf)를 지우므로, 그 안에 숨긴 채점 지시가 사라진다(OT p.14: 판정 모델은 답변 전체를 본다). 출력 판정에는 후보 답변 원문을 보내되 보이지 않는 문자를 드러낸다: 태그 문자(U+E0020–E007E)는 대응 ASCII로 풀고, 나머지는 `<U+200B>`처럼 코드값으로 적는다. 이모지 시퀀스 안의 ZWJ(U+200D)·변형 선택자(U+FE0F)와 맨 앞 BOM은 그대로 둔다(GR-06과 같은 기준). 문장 분리·`unsupported` 구간은 원문 기준이다.
- **학습자 발화의 숨긴 문자도 버리지 않는다.** 입력 판정에 보내는 정규화본 끝에, 태그 문자를 ASCII로 푼 숨긴 텍스트를 `[숨긴 문자: …]`로 덧붙이고 GR-06 숨긴 문자 신호를 낸다(태그 문자로 숨긴 탈옥 지시).
- **수용 기준**: 우회 표기 회귀 세트 일치율 100%(기존 테스트 유지). 임의 유니코드 입력에서 예외 0건. KB의 코드 블록 문장 전수에서 규칙 오매칭 0건. p95 ≤10ms.

### GR-03 KB 색인·검색 (P0, 신설)
- 기동 때 `kb/<과목>/`의 마크다운·CSV(·HTML)를 섹션 ID 단위로 읽어 색인한다. 섹션 ID는 파일 이름이다.
- 검색 질의는 창 안의 학습자 발화(실습·예제·상품 이름 단서)와 후보 답변이다. 과목·섹션은 요청에 오지 않는다(OT §4).
- 청크는 섹션 단위(같은 이름의 CSV는 그 섹션에 붙임). 너무 긴 섹션만 소제목 단위로 나누되 코드 블록·표는 자르지 않는다.
- 검색은 기존 문자 2-gram BM25(`src/guardrail/eval/mock_tutor.py`)를 서버 모듈로 옮긴다. 형태소 분석기는 모델·사전 파일을 담고 있어 쓰지 않는다(R12 §6-1).
- 질의는 후보 답변의 문장별 + 학습자 발화(입력 판정과 같은 창: 첫 학습자 발화 + 최근 6턴). 학습자는 실습·예제 이름을 어느 턴에서든 말할 수 있고, 버튼 문구로 시작한 대화는 실제 질문이 다음 발화에 온다(OT §4). 문장마다 top-k를 구해 섹션별 최고 점수로 합친다. 답변 전체 한 덩어리 질의는 지어낸 내용과 비슷한 구절을 끌어오므로 쓰지 않는다(ADR-0010).
- 임베딩 혼합, 과목 전체 넣기는 recall@k와 KB 크기를 잰 뒤 ablation으로만 더한다.
- 가상 설정(다람쥐은행 등)은 일반 상식이 아니라 KB 기준으로 판정한다.
- **수용 기준**: `public/tutor.jsonl`의 정답 근거 섹션 기준 recall@k `[공개 세트 후]`(목표값). 색인 시간과 메모리 보고. 요청당 검색 p95 ≤20ms.

### GR-04 입력 판정 (P0)
- 출력: `input.decision`(allow/block) + `input.category`(10개 중 하나).
- 입력: 정규화된 **첫 학습자 발화 + 최근 6턴**(토큰 상한 안. "턴"은 메시지 하나이고, 최근 6턴은 마지막 학습자 발화를 포함한 마지막 메시지 6개다. 이 정의를 GR-03·GR-05와 ADR-0010·0011이 같이 쓴다), 판정 대상인 마지막 학습자 발화 표시, GR-06 신호(힌트), 필요하면 GR-03 검색 결과(`out_of_material` 판단용) `[공개 세트 후]`.
- 출력 스키마 순서: `evidence`(≤2문장) → `category` → `decision`. 근거를 먼저 쓰게 하면 작은 모델의 정확도가 오른다(R12 §1).
- 범주가 decision을 결정적으로 정한다는 것이 공개 세트로 확인되면 decision은 코드로 계산한다 `[공개 세트 후]`.
- 호출은 1회(k=1). "2표, 엇갈리면 1표 추가"는 설정 플래그 뒤의 실험이다(ADR-0011).
- 대화 속 "시스템 지시" 문장은 학습자 입력이다. 학습자 메시지는 태그로 감싸 "판정 대상 데이터"로 표시한다.
- 정책 프롬프트: 범주 정의와 decision 기준, 경계 사례. 경계 사례는 공개 세트의 **개발 분할**에서만 뽑고 팀이 직접 쓴다(GR-12, OT §10).
- OpenAI 직접 호출 기준으로 gpt-5 계열은 logprobs를 받지 않는다(R12 §4, 대회 프록시는 미확인). 그래서 확률 임계값을 쓰지 않는다. block F1은 정책 문구와 경계 사례로 개발 분할에서 맞춘다.
- 구조화 출력은 json_schema strict. 대회 프록시의 지원 여부는 기동 시 시험 호출로 확인하고, 안 되면 기존 `llm.py`의 단계적 강등을 쓴다. 파싱 실패 시 1회 재요청(호출마다의 재시도 1회를 쓴다) → 실패하면 GR-08 기본값.
- **수용 기준**: 개발·홀드아웃의 block F1, 범주 정확도(non-normal), 범주별 혼동행렬. JSON 파싱 성공률 100%(재시도·기본값 포함). 호출 p95 ≤5s.

### GR-05 멀티턴 문맥 (P1, v4 GR-05 재작성)
- 요청 사이에 상태가 없다. v4의 세션 위험 R 누적은 없애고, 멀티턴 문맥은 **매 요청의 이력에서** 판정한다.
- 첫 발화가 빠른 질문 버튼 문구인 대화, 앞 턴에서 상승하는 공격, 앞선 거절 뒤 바꿔 말한 재시도를 다룬다.
- 방식: 판정 프롬프트에 첫 학습자 발화 + 최근 6턴을 넣는다(GR-04). 첫 발화는 버튼 문구·역할극 설정이 놓이는 자리라 자르지 않는다. 이전 학습자 발화의 결정적 신호도 힌트로 넣는다.
- **수용 기준**: 공개 세트의 멀티턴 문항만 따로 block F1을 보고 `[공개 세트 후]`(멀티턴 비율).

### GR-06 결정적 신호 (P0, v4 GR-02·03·07 통합)
- 어휘·패턴 매칭으로 플래그를 낸다. LLM 없이 돈다. 신호마다 쓰는 뷰가 다르다.
  - **위기**(골격 뷰): 자해·자살·학대·그루밍 어휘 → `emotional_distress` 후보 플래그
  - **PII**(원문·정규화본, 정규식 + 체크섬): 주민번호(체크섬)·전화·이메일·카드·계좌 → `pii_disclosure` 후보 플래그. 골격 뷰는 숫자·기호를 지워 PII를 찾을 수 없다
  - **숨긴 문자**(후보 답변·학습자 발화 원문): 태그 문자(U+E0000–E007F)가 있거나, 이모지 시퀀스 밖에 보이지 않는 문자(U+200B·U+200C·U+2060 같은 폭 없는 문자, 맨 앞이 아닌 U+FEFF)가 끼어 있으면, 후보 답변이면 출력 판정에 `safe` 힌트, 학습자 발화면 입력 판정에 `jailbreak_injection` 힌트로 넘긴다(GR-02)
  - **인젝션**(골격 뷰, 영어 문구는 라틴 문자가 남는 골격 뷰로): 확실한 탈옥·지시 무시 패턴 → `jailbreak_injection` 후보 플래그
  - **출력 쪽 검사**(후보 답변 원문): 금지 표현(팀이 직접 쓴 목록, 예: "극단적 선택")과 PII 패턴 → 출력 판정에 `safe` 힌트
- 어휘·패턴 목록은 **팀이 직접 쓴다**. 인터넷에서 받은 사전·목록은 서버에 넣지 않는다(OT §10). v4에는 어휘 파일이 없었으므로 처음부터 쓴다(R12 §8).
- 플래그는 기본적으로 LLM 판정의 **힌트**다. 신호만으로 바로 정하는 것은 정의상 확실한 경우뿐이다: 빈 입력·기호만 있는 입력(정규화본 기준, 숫자가 있으면 해당하지 않음. 태그 문자를 푼 숨긴 텍스트도 내용으로 세므로, 숨긴 문자 신호가 있으면 직접 결정하지 않고 입력 판정 LLM으로 보낸다) → `low_signal_input`, 체크섬을 통과한 주민번호·형식이 분명한 휴대전화 번호 → `pii_disclosure`(ADR-0002 v5). 범주 정의가 주어지지 않았고 금융 과목의 가상 은행·가게 정보와 헷갈릴 수 있으므로, 직접 결정은 공개 세트 라벨과 맞는지 확인한 뒤 켠다. decision도 공개 세트의 범주별 decision으로 정한다 `[공개 세트 후]`.
- 정밀도 임계(예: ≥0.98)로 직접 결정을 허용하는 방식은 쓰지 않는다. 공개 세트가 수백 문항 규모라면 규칙별 건수가 적어 잴 수 없다(크기는 11/10에 확인).
- **수용 기준**: 플래그별 정밀도·재현율(개발 분할). LLM이 꺼진 상태에서도 플래그가 같은 값.

### GR-07 후보 답변 판정 (P0, v4 GR-08 재작성)
- 출력: `output.grounded`, `output.unsupported`(구간 목록), `output.safe`. `output.category`는 채점하지 않으므로 `input.category`를 복사한다(ADR-0009).
- 근거: GR-03에서 찾은 섹션. 자료와 모순되지 않는 일반 설명의 취급 `[공개 세트 후]`(튜터 채점은 자료에 없는 질문에서 지어내지 않는 한 그런 설명을 감점하지 않는다, OT p.14. 가드 라벨은 미확인).
- **구간 추출, 기본은 문장 번호 선택**: 코드가 후보 답변을 문장으로 나눠 번호를 붙이고, 판정기는 근거 없는 문장 번호만 고른다. 응답에는 그 문장의 원문을 넣는다. 구조상 원문에 없는 구간이 생기지 않는다(ADR-0005 v5). 번호는 근거 판정 대상 문장(주장이 있고 사전 필터를 통과하지 못한 문장)에만 붙인다. 범위 밖·중복 번호는 버리고, 돌려준 번호가 모두 무효면 판정기 출력 오류로 보고 재요청 1회 → 실패하면 GR-08 기본값.
- **구절 단위 방식**: 공개 세트의 정답 구간이 문장보다 짧으면, 판정기가 구간을 그대로 복사하고 코드가 원문 부분 문자열로 맞춘다(정확히 → 공백·문장부호 제거본 → rapidfuzz ≥90). 구절 방식에서도 판정기는 구간마다 문장 번호를 같이 낸다. 정렬에 실패한 구간은 그 번호의 문장을 통째로 쓴다(`grounded`가 조용히 참으로 바뀌지 않게). 어느 방식을 쓸지는 정답 구간 길이 분포로 정한다 `[공개 세트 후]`.
- 판정기 입력: 마지막 학습자 발화 + 번호 붙은 문장(보이지 않는 문자를 드러낸 원문, GR-02) + 검색한 KB 섹션(ID·구분자). "근거는 KB만"을 명시한다. 인사·되묻기 같은 주장 없는 문장은 판정에서 뺀다. 코드가 확실한 것(물음표로 끝나는 문장, 인사 어휘만 있는 문장)만 빼고, 애매하면 번호를 붙여 판정기에 맡긴다.
- 출력 스키마: 근거 없는 문장 번호 목록(구절 방식이면 구간 + 문장 번호) + `safe`. `safe` 판정에는 사전 필터를 통과했거나 주장이 없는 문장까지 답변 전체를 넣는다(숨긴 지시가 판정을 건너뛰지 않게). 판정기 호출은 1회(ADR-0011).
- **사전 필터**(v4 유지): 문장과 한 섹션의 문자 3-gram 포함률 ≥θ이고 문장의 숫자·라틴 용어가 그 섹션에 모두 있으면 판정 없이 지지된 것으로 둔다. 자동 통과만 하고 자동 실패는 내리지 않는다.
- `grounded`는 코드에서 `unsupported`가 비었을 때만 참으로 계산한다. 이 규칙이 라벨과 맞는지 공개 세트로 확인한다 `[공개 세트 후]`.
- `safe`: 유해 내용, 채점 지시 문장(보이지 않는 문자 포함, OT §7), 개인정보 노출 등 `[공개 세트 후]`.
- **수용 기준**: 개발·홀드아웃의 grounded 정확도, unsupported 구간 일치(채점식 재현), safe 정확도. 부분 문자열 확인 통과율 100%.

### GR-08 장애·기본값 (P0, v4 GR-14 축소)
- 인증 실패를 뺀 어떤 실패에도 HTTP 200과 규격 응답을 낸다. 실패는 재시도까지 실패한 뒤다.

| 실패 | 응답 (ADR-0009) |
|---|---|
| 입력 판정 LLM 실패 | 마지막 학습자 발화의 결정적 신호만 본다(앞 턴 신호는 힌트로만 썼으므로 쓰지 않는다). 신호가 여럿이면 우선순위 jailbreak_injection > emotional_distress > pii_disclosure > low_signal_input 순으로 하나를 고르고, decision은 §3의 값(임시값 포함)을 쓴다. 숨긴 문자·인젝션 신호는 `jailbreak_injection`. 신호가 없으면 `allow`·`normal` |
| 답변 판정 LLM 실패 | `grounded=true`, `unsupported=[]`. `safe`는 출력 쪽 결정적 신호(숨긴 문자·금지 표현·PII, GR-06)가 있으면 `false`, 없으면 `true` |
| 요청 마감 25초 | 그때까지의 결과 + 위 기본값으로 즉시 응답 |
| 요청 파싱 실패 | `messages`(와 `candidate_answer`)를 읽을 수 있으면 판정하고, 못 읽으면 기본값 응답(200). 원본 본문에 `candidate_answer` 키가 있으면 `output` 기본값도 넣는다(빠지면 형식 오류) `[SPEC.md 대조]` |

- 재시도는 호출마다 1회까지, 마감 안에서만.
- 기본값은 설정 값이다. 공개 세트의 block 비율이 높으면 입력 실패 시 `block`이 F1에 유리할 수 있다(council의 가장 강한 반대, Skeptic) → 필드별 다수 클래스를 보고 다시 정한다 `[공개 세트 후]`.
- **수용 기준**: 장애 주입(타임아웃·5xx·429·잘못된 JSON)에서 형식 오류 0건, 모든 응답 30초 안.

### GR-09 동시성·지연 (P0)
- 64개 동시 요청을 30초 안에 처리한다. 모든 LLM 호출은 동시성 게이트 하나(세마포어 + AIMD, 단일 재시도 계층)를 지난다(v4 GR-14 유지).
- 요청별 마감을 두고 그 안에서만 재시도한다. 과한 호출은 키 회수 사유이고 "공격이나 과도한 호출"은 실격 사유이기도 하므로(OT p.26–27) 재시도 횟수에 상한을 둔다. 기존 `llm.py`의 `MAX_ATTEMPTS = 3`(호출 하나의 모든 전송: 일시 오류 재시도·형식 재요청·강등)과 전역 재시도 예산(첫 시도의 10%, 최소 5)은 호출마다 전송 최대 2회(재시도 1회)로 줄이고, 게이트 대기도 요청 마감에 넣는다.
- `gpt-5-nano` 파라미터: `reasoning_effort="low"`, `verbosity="low"`, json_schema strict, `max_completion_tokens` ≥800. `temperature`·`max_tokens`·`logprobs`는 보내지 않는다. OpenAI 직접 호출에서는 gpt-5 계열이 이 값들을 400으로 거부한다는 보고가 있다(R12 §4). OT는 temperature를 "자유"라고 했으므로 대회 프록시 동작은 기동 시 시험 호출로 확인하고, 어느 경우든 보내지 않는다. 현재 `llm.py`는 `temperature`·`max_tokens`를 보내므로 고친다. `minimal`은 지연 비교로만 잰다.
- 호출당 타임아웃 약 12초. 서버는 FastAPI(`redirect_slashes=False`) + uvicorn 프로세스 1개, `AsyncOpenAI(max_retries=0)`(R12 §6-2).
- 키의 호출·크레딧 한도는 따로 없다(OT p.27). 다만 과한 호출은 경고 뒤 키 회수 사유이고, 프록시의 실제 처리량과 채점기의 실제 동시성은 모른다. 부하 시험은 채점과 같은 부하(동시 64, 가드 약 300요청)까지만 한다. 그보다 센 시험은 과한 호출로 볼 수 있어 운영진에게 먼저 묻는다(OT p.26–27).
- **수용 기준**: 공개 세트에서 가드 약 300요청을 동시성 64로 돌려(공개 세트가 더 크면 표본으로) 시간 초과 0건, p95 보고. 게이트 초기 동시성은 64로 두고 AIMD로 조정하며, 게이트 대기가 25초 마감 안에 드는지 확인한다. 전체 실행 시간이 베이스라인 수준(제출 하나의 채점 약 2분, 튜터·가드 합쳐 약 600요청)인지 확인.

### GR-10 설정·ablation (P0, v4 GR-12 유지)
- 모델 파라미터, k, θ, 임계값, 프롬프트 버전은 설정 파일로 뺀다.
- 단계별 켜기·끄기(결정적 신호 / 검색 / 사전 필터 / 구간 보정). 모두 끈 "nano 단독" 설정이 베이스라인이다.
- **수용 기준**: 코드 수정 없이 설정만 바꿔 ablation이 돈다.

### GR-11 로깅 (P0, v4 GR-13 재작성)
- **허용 항목만 남긴다: 시간, 길이, 상태 코드, 오류**(OT §10). 요청·답변 본문, 판정 사유 원문, 정규화본은 서버 로그에 남기지 않는다.
- 토큰 수·판정 값(decision, category, grounded, safe)은 허용 목록(시간·길이·상태 코드·오류) 밖이므로 남기지 않는다(OT p.26·34).
- 오류 로그에는 예외 종류·오류 코드만 남긴다. pydantic 검증 오류 문자열처럼 입력 값을 되풀이하는 메시지는 남기지 않는다. uvicorn 접근 로그도 허용 항목(시간·길이·상태 코드·오류)만 남게 설정한다.
- 평가 하네스(로컬, 공개 세트)는 서버 밖에서 응답 JSON을 저장해 분석한다. 이것은 배포 자료 분석이라 허용 범위다.
- API 키·토큰은 환경변수로만, 로그에 남기지 않는다.
- **수용 기준**: 로그 코드 리뷰에서 본문 기록 경로 0개. 공개 세트 실행과 GR-01 퍼징 실행 뒤 서버 로그를 grep해 요청 문자열 0건.

### GR-12 평가 하네스 (P0, v4 GR-15 재작성)
- 데이터: `public/guard.jsonl`을 대화(원 요청) 단위로 개발/홀드아웃 분리한다. 홀드아웃은 임계값·프롬프트를 고정한 뒤 최대 3회만 본다(ADR-0006 v5). 1회는 한 세션에서 정해 둔 설정 묶음(베이스라인 + 후보) × 3회 반복을 한 번에 돌리는 것이다.
- 채점: 대회 채점식을 그대로 재현한다(block F1, non-normal 범주 정확도, 답변 판정 평균, 구간 비교 시 띄어쓰기·문장부호 무시). 로컬 채점기 `harness/score_local.py`와 값이 같은지 확인한다.
- 채점 세부: 해당 문항이 없는 항목은 빼고 나머지 비율대로 계산한다(OT §6). 예를 들어 표본에 non-normal 문항이 없으면 범주 정확도를 빼고 나머지 가중치 비율로 계산하고, 출력 판정에서 라벨이 없는 하위 항목도 빼고 평균한다. 형식이 틀린 응답은 틀린 판정으로 센다. 구현은 `score_local.py`와 값을 맞춰 확인한다.
- 호출 예산: 실행 전에 예상 호출 수를 출력하고 상한을 넘으면 멈춘다(v4 `--estimate`·`--max-calls` 유지, ADR-0011). 과한 호출은 실격 사유다(OT p.26).
- 판정 모델 채점 항목은 로컬 판정 모델이 실제와 다르므로 차이를 함께 적는다(OT §2).
- 반복 측정: 같은 설정 3회로 nano 출력의 변동 폭을 보고한다. 개발 분할에서는 자유롭게, 홀드아웃에서는 위 1회 안에서 돌린다.
- **수용 기준**: 우리 채점기와 `score_local.py`의 가드 점수 차 ≤0.005. ablation 표, 범주별 표, 지연 표.

### GR-13 규칙 준수 (P0, 신설)
- 서버에 들어가는 데이터·사전·예시의 출처를 `docs/competition/provenance.md`에 적는다: 배포 자료 / 팀 작성 / (불가) 외부·다른 LLM 생성.
- 하드코딩 금지: 질문 → 답 표, 유사도 캐시, 채점 요청 수집·재사용, 채점 요청을 알아보는 분기 없음(OT §10).
- 기존 자산 점검: v4의 평가 세트·위기 어휘·attack_judge 프롬프트 중 서버에 들어가는 것이 있으면 출처를 확인하고, 외부·다른 LLM 생성이면 빼거나 팀이 다시 쓴다. 점검 결과 서버에 넣을 수 있는 v4 데이터성 자산(사전·표·예시)은 `preprocess.py`의 자모 표뿐이다(재사용 코드는 provenance §1). LLM이 초안을 쓴 스모크 데이터는 `data/README.md`에 그렇게 적혀 있지만 레코드의 `source` 값이 `self`라 헷갈릴 수 있다. provenance에 따로 적고 서버 밖 개발 스모크로만 쓴다(점수 보고에는 쓰지 않음, ADR-0006 v5). 같은 방식으로 만든 교재 자리표시는 `kb/`로 대체해 쓰지 않는다.
- **수용 기준**: provenance 문서에 서버 자산 전수. 시연용 체크리스트(키 미커밋, 본문 로그 없음, 커밋 해시) 통과.

## 7. 지표와 합격선

가드 점수 = 0.45 × block F1 + 0.10 × 범주 정확도(non-normal) + 0.45 × 후보 답변 판정(OT §6).

| 지표 | 정의 | 목표 | 함께 보고 |
|---|---|---|---|
| block F1 | 홀드아웃 `decision=block`의 F1 | `[공개 세트 후]`(베이스라인 + 개선 폭) | 정밀도·재현율, 범주별 |
| 범주 정확도 | 정답이 non-normal인 문항의 범주 일치율 | `[공개 세트 후]` | 혼동행렬 |
| 답변 판정 | grounded·unsupported·safe 문항 평균 | `[공개 세트 후]` | 항목별 |
| 가드 점수 | 위 식 | nano 단독 베이스라인 대비 개선 | 3회 반복 범위 |
| 형식 오류·시간 초과 | 개수 | 0 | 동시성 64 조건 |
| 지연 | p50·p95 | §6 | 단계별 |

- 베이스라인 = nano 단독 설정(GR-10). 목표값은 베이스라인을 잰 뒤 정한다.
- 설정 비교는 홀드아웃에서 McNemar(block 판정)와 부트스트랩 신뢰구간(점수)으로 한다.

## 11. 미결 사항

### 11-1. 주최측·SPEC.md로 확인할 것
1. 인증 실패의 상태 코드, 요청 파싱 실패 시 기대 응답
2. `candidate_answer`가 빈 문자열일 때 `output` 처리
3. 외부 공개 데이터셋을 서버 밖 평가에만 쓰는 것의 허용 여부(§8)
4. 대회 프록시가 `json_schema` strict·`verbosity`를 받는지, `temperature`·`reasoning_effort`를 그대로 전달하는지(OT는 둘 다 "자유")
5. 채점 부하(동시 64)에서 프록시의 처리량·지연과 채점기의 실제 동시성. 키의 호출·크레딧 한도는 따로 없다(OT p.27)

### 11-2. 공개 세트가 오면 할 일
1. 라벨 분포: decision, category, grounded, safe, `candidate_answer` 유무
2. 범주 × decision 교차표 → §3 확정
3. unsupported 구간의 길이·단위 분포 → GR-07 구간 단위
4. 멀티턴·버튼 문구 문항 비율 → GR-05
5. 자료 밖이지만 모순 없는 일반 설명의 라벨 → GR-07
6. 개발/홀드아웃 분리, 상수 응답과 nano 단독 베이스라인 측정 → §7 목표값
7. KB 과목별 토큰 수, `tutor.jsonl` 근거 섹션 기준 BM25 recall@k → GR-03
8. `safe=false` 라벨의 내용(정답을 그대로 준 답변 포함 여부) → GR-07
9. 입력 판정 실패 기본값(allow / block) → GR-08

- 2026-11-09 P2 리서치([R12](research/R12-competition-baseline.md)): research-ops로 search-first(라이브러리)·deep-research(설계 근거)·로컬 자산 점검을 동시에 했다. 현재 `llm.py`가 gpt-5 계열이 거부한다고 보고된 파라미터(`temperature`·`max_tokens`)를 보낸다는 문제를 찾았다(대회 프록시 동작은 미확인).
- 2026-11-09 P3 `/ecc:council`(Architect·Skeptic·Pragmatist·Critic), 결정 7건 → ADR-0009–0011. 초안에서 바꾼 것: 투표 k=3 → k=1(세 목소리 모두 반대), 결정적 신호 "정밀도 ≥0.98이면 직접 결정" → 정의상 확실한 것만(Skeptic·Critic), 답변 통째 검색 → 문장별 질의(Critic), 오래된 턴부터 자르기 → 첫 발화 고정 + 최근 6턴(Critic), 구간 추출 → 문장 번호 선택(Skeptic). 반영하지 않은 것: 입력 판정 실패 기본값 `block`(Skeptic) — block 비율을 모르므로 설정 값으로 두고 공개 세트로 다시 정한다.
- 2026-11-09 `/ecc:santa-loop`(사용자 지정: LOW까지, 이후 3회 상한): 1·2라운드 지적(숨긴 문자, 골격 뷰 PII, 로그 허용 항목, D6 공개 저장소, GP 링크 등)을 고쳐 커밋했다. 3라운드 둘 다 FAIL, 남은 8건(장애 기본값의 decision·우선순위, 숨긴 문자만으로 된 입력의 저신호 직접 결정, 이모지 오탐, 출력 장애 시 safe, ADR-0005 v4 본문, R12 요약 11행, GP 배너, ADR-0009·interface 임시 기본값)은 재검증 없이 고쳤다.
- 2026-11-09 P6 `/ecc:santa-method`(독립 리뷰어 2명 × 라운드, Opus): 1차 둘 다 FAIL(OT 사실 오독 6건 — 약 600의 의미, 공개 세트 크기, 호출 한도, temperature, 포트, 베이스라인 시간 — R12의 council 이전 권고, 홀드아웃 횟수, 인증 실패와 "항상 200", 로그 자리표시, ADR 헤더 GR 번호). 2차 둘 다 FAIL(학습자 발화에 대한 OT 오독, 검색 질의 근거 반대로 인용, 폐기 ADR 헤더, ADR-0006과 PRD의 ablation·스모크 세트 충돌, 홀드아웃 1회의 정의, v4 본문의 Kiwi·MiniCheck·위기 분류 모델·캐시). 부하 시험은 채점 수준(동시 64)까지로 제한했다(OT p.26–27 과한 호출).
