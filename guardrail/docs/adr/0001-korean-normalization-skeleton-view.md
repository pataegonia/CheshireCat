# ADR-0001: 한국어 정규화와 골격 뷰

**Date**: 2026-10-30
**Status**: proposed
**Deciders**: danielcho02
**PRD**: GR-02, GR-06 (v4: GR-01, GR-02, GR-07)

## v6 수정 (2026-11-10, R13 council)

이 블록이 아래 v5 블록과 본문보다 우선한다. PRD v6 GR-02·GR-06 기준이다. 바뀐 것:
- **뷰 구성**: 정규화본(LLM·kNN·LR용)과 **붙인 뷰**(정규식 전용, 한 음절짜리 한글 토큰이 공백 하나를 사이에 두고 2개 이상 이어질 때만 그 공백을 지운 것. 일반 띄어쓰기는 붙이지 않아 "자 살펴볼까요" → "자살펴…" 같은 경계 넘는 오매칭을 막는다)를 만든다. 정규화본에는 NFKC를 쓰지 않는다(본문 유지, PRD v6 GR-02). 공개 세트에 "광 고", "시 드", "발 급 수 수 료"처럼 음절 사이를 띄운 표기가 11건 있다(normal 7, [R13-A 부록](../research/R13-public-set-analysis.md#부록-길이형식유니코드), [R13 §1 M8](../research/R13-design-research.md#1-근거-정리-research-ops-형식)). 띄우기와 자모 축약은 범주와 무관한 잡음이라 범주 단서로 쓰지 않는다.
- **골격 뷰는 v6 서버 경로에서 쓰지 않는다.** 소비자였던 위기·PII·인젝션 어휘 목록이 삭제됐다(PRD GR-06). 아래 본문의 골격 뷰 설계와 경계 규칙은 기록으로 남긴다.
- **신호의 지위**: 입력 쪽에서 LLM 없이 정하는 것은 저신호 직접 판정(자모·문장부호·이모티콘만 + 앞 대화 있음 → `low_signal_input`) 하나다(ADR-0012). v5의 PII 직접 결정은 없앤다. 출력 쪽 결정적 규칙은 거절 정규식(`safe`에만 쓴다. 3단 ①에는 쓰지 않는다), 숫자·리터럴 규칙(3단 ②), 숨긴 태그 문자(`safe=false`)다(ADR-0014, [R13 D5·D6](../research/R13-design-research.md#3-결정-d1d10)). 나머지는 없다.
- **Kiwi는 쓰지 않는다**([R13 D7](../research/R13-design-research.md#3-결정-d1d10)). SPEC §7.1은 사전이 딸린 형태소 분석기를 허용하지만 `kiwipiepy_model`의 언어모델 파일은 "미리 학습된 모델"과 경계가 모호하고([R13-B2 §2](../research/R13-B2-libraries.md#2-규정-판정-기준과-모호한-지점)), 문자 n-gram으로 충분하다.
- **숨긴 문자**: 공개 세트 400행에 보이지 않는 문자는 0건이었다. 그래도 후보 답변의 태그 문자(U+E0020–E007E)는 ASCII로 드러내고(구간은 원문 기준), 학습자 발화의 태그 문자는 풀어서 정규화본 끝에 `[숨긴 문자: …]`로 붙인다(PRD GR-02, SPEC §6).
- 자모 정규식(저신호 판정)은 NFKC가 호환 자모를 조합용 자모로 바꾼다는 점을 고려해 두 범위를 함께 넣는다([R13-A 부록](../research/R13-public-set-analysis.md#부록-길이형식유니코드)).

## v5 수정 (2026-11-09)

정규화본·골격 뷰 두 뷰와 처리 순서는 그대로 쓴다(PRD v5 GR-02). 단 정규화본이 지우는 보이지 않는 문자는 후보 답변에서는 지우지 않고 드러낸다(숨긴 채점 지시, PRD GR-02). 아래 본문 중 바뀐 것:
- **번호**: 본문의 번호는 v4다. v4 GR-01(전처리) → v5 GR-02, v4 GR-02(위기 탐지) → v5 GR-06(결정적 신호), v4 GR-07(출력 코드 검사) → v5 GR-06·GR-07(카나리아·`[S#]` 검사는 삭제, 금지 표현은 `safe` 보조, PRD 부록 A). ③·⑤·⑦은 v4 PRD §4의 단계(규칙·입력 판정·카나리아)이고 v5 §4의 번호와 다르다.
- **매칭 용도 표**: "결정적 차단"은 없다. 골격 뷰 매칭 결과는 입력 판정의 힌트이고, 신호만으로 바로 정하는 것은 정의상 확실한 `low_signal_input`·`pii_disclosure`뿐이며 공개 세트 라벨로 확인한 뒤 켠다(ADR-0002 v5). PII는 숫자·기호가 지워지는 골격 뷰가 아니라 원문·정규화본에서 정규식 + 체크섬으로 찾는다(PRD GR-06). 카나리아는 v5에서 삭제됐다(PRD §14). v5에서 골격 뷰 매칭(위기·인젝션)은 모두 힌트라서 "통째로 덮어야 인정" 경계 규칙은 쓰지 않는다. 경계를 넘는 매칭도 힌트로 인정하고, 오탐은 입력 판정 LLM이 거른다. 직접 결정(빈 입력·PII)은 골격 뷰를 쓰지 않는다.
- **혼동 문자 사전(P1)**: 쓴다면 팀이 직접 쓴다. Unicode `confusables.txt` 같은 인터넷 목록에서 가져오지 않는다(OT p.25). 쓸 수 있는지 애매하면 쓰기 전에 운영진에게 묻는다.
- **회귀 세트**: "수식·코드가 섞인 정상 문장 ≥200건"은 v5에서 KB의 코드 블록 문장 전수로 바뀐다(PRD GR-02 수용 기준).

## Context

학생들은 자모 분리(ㅂㅏㅂㅗ), 초성(ㅅㅂ), 전각 문자, 제로폭 문자, 숫자 끼움(시1발, 시①발) 같은 표기로 필터를 피한다.

NFKC만으로는 이를 제대로 복원하지 못한다.
- 초성과 모음은 음절로 합친다.
- 하지만 모음 없이 뒤따르는 자음을 받침으로 붙이지는 않는다.
- 겹받침을 둘로 나눠 쓴 것(ㄷㅏㄹㄱ)도 복원하지 못한다.
- 단독 모음과 겹자모는 조합형 낱자모로 바꿔 버린다.

그렇다고 받침을 무조건 붙이면 "야ㅅㅂ"이 "얏ㅂ", "좋아ㅋㅋ"가 "좋앜ㅋ"가 된다. 이미 완성된 음절 뒤에 쓴 초성 약어를 망가뜨리는 것이다(PR #1 santa 검토에서 발견).

반대로 공백, 숫자, 기호를 모두 지우면 수식과 코드가 망가진다. 이 튜터에서는 수식과 코드가 정상 질문의 상당 부분을 차지한다.

## Decision

원문은 그대로 두고 두 가지 뷰를 따로 만든다. 구현은 `src/guardrail/preprocess.py`다.
- **정규화본**: LLM 판정에 보낸다. **NFKC를 쓰지 않는다.** NFKC는 x²를 x2로, ½을 1⁄2로 바꿔 수식의 뜻을 바꾸기 때문이다. 처리 순서는 다음과 같다.
  1. 보이지 않는 문자를 제거한다. 대상은 서식 문자(Cf), 변형 선택자, 결합 문자 접착자, 몽골 FVS, 한글 채움 문자다.
  2. 전각·반각만 접는다. ｓ는 s로, 반각 자모는 호환 자모로 바꾼다. 미할당 코드포인트는 그대로 둔다.
  3. NFC로 완전한 조합형 음절을 합친다. 그 뒤 남은 조합형 낱자모는 호환 자모로 바꾼다.
  4. 호환 자모 구간을 두벌식 입력기 규칙으로 직접 조합한다.
     - 받침과 겹받침은 다음 글자가 모음이 아닐 때만 붙인다.
     - 모음이 없는 구간(ㅅㅂ, ㅋㅋ)은 그대로 둔다.
     - 이모티콘은 조합하지 않는다. 같은 자음이 반복된 뒤(ㅋㅋㅠ)와 ㅠ·ㅜ 반복(ㅋㅠㅠ)이 여기에 해당한다.
- **골격 뷰**: **어휘 사전 매칭 전용**이다(위기 어휘, 카나리아, 확실한 공격 패턴). 재현율을 우선한다. 처리 순서는 다음과 같다.
  1. 위 1–2단계를 적용한다.
  2. 호환 자모 구간을 뺀 나머지에 NFKC를 적용한다. ①·²·𝟏은 숫자가 되고, 원문자 자모 ㉨는 ㅈ이 된다. 그 뒤 조합형 낱자모를 호환 자모로 바꾼다.
  3. 공백·기호·숫자를 제거한다.
  4. 같은 모음 반복을 하나로 줄인다(ㅈㅏㅏ → ㅈㅏ).
  5. 이모티콘 예외 없이 자모를 조합한다.
  6. 음절 뒤에 그 음절의 중성과 같은 모음을 늘여 쓴 것을 지운다(시ㅣ발 → 시발). 그다음 소문자로 바꾼다.
  7. **라틴 문자는 남긴다.** 영어 공격 문구("ignore previous")를 매칭해야 하기 때문이다.
- 이미 완성된 음절은 자모 구간에 들어가지 않는다. 그래서 공백을 지운 뒤에도 앞 단어가 뒤 초성을 받침으로 흡수하지 않는다("나 ㅈㅅ" → "나ㅈㅅ").

**골격 뷰 매칭 규칙 (GR-02·③·GR-07 구현 시 지킬 것)**

골격 뷰는 원래 단어 경계를 지운다. 그래서 짧은 어휘가 경계를 넘어 정상 문장에 걸린다.
- "자, 살펴볼까요?" → "자살펴볼까요"에 "자살"이 걸린다.
- "오늘 17시 발표" → "오늘시발표"에 "시발"이 걸린다.

반대로 실제 위기 발화도 경계를 넘는다. "자 살하고 싶어", "죽고 싶어"가 그렇다. 경계 규칙 하나로 두 경우를 함께 가를 수는 없다. 그래서 **매칭 결과가 무엇을 하느냐**에 따라 규칙을 나눈다.

| 매칭 용도 | 결과 | 경계 규칙 |
|---|---|---|
| 위기 어휘(GR-02) | 플래그만 단다. 차단하지 않고, 오탐은 ⑤가 완화한다 | 경계를 넘는 매칭도 인정한다(재현율 우선) |
| 확실한 규칙(③), 카나리아(⑦) | 결정적 차단 | 지워진 구분자를 넘으면, 걸친 원래 조각을 **모두 통째로 덮어야** 인정한다. "ㅂ ㅏ ㅂ ㅗ"처럼 한 글자짜리 조각은 통째로 덮인다 |

이 규칙을 구현하려면 골격 뷰의 각 글자가 원문의 어느 조각에서 왔는지 알아야 한다. GR-02·③을 착수할 때 `skeleton`에 원문 조각 경계를 함께 돌려주는 함수를 추가한다. 위 정상·위기 문장은 매처의 회귀 테스트로 고정한다.

## Alternatives Considered

### NFKC만 적용
- **Pros**: 한 줄이고 표준이다.
- **Cons**: 자모 분리가 음절로 복원되지 않는다. 숫자 끼움과 제로폭 문자 일부도 남는다.
- **Why not**: 한국어 우회 표기의 주요 유형을 놓친다.

### 하나의 공격적 정규화본을 모든 단계에 사용
- **Pros**: 경로가 하나라 단순하다.
- **Cons**: 수식, 코드, 숫자가 지워진 채 LLM과 근거 판정에 들어간다.
- **Why not**: 과잉 거절과 근거 판정 오류가 늘어난다(council Critic 지적).

### 외부 한국어 정규화 라이브러리
- **Pros**: 이미 만들어져 있다.
- **Cons**: 받침 결합과 우회 표기 복원을 함께 하는 유지보수 중인 패키지를 찾지 못했다(R4 search-first).
- **Why not**: 필요한 것이 표준 라이브러리 `unicodedata`에 약 100줄을 더하는 정도다.

## Consequences

### Positive
- 의존성이 없다. p95 ≤10ms가 목표다(8천 자 입력에서 약 6ms 측정, 검토자 실측).
- 규칙 매칭이 우회 표기에 강해진다. LLM에는 수식 기호가 바뀌지 않은 정규화본이 간다.

### Negative
- 뷰가 둘이라 어느 단계가 어느 뷰를 쓰는지 테스트로 고정해야 한다.
- 야민정음(댕댕이→멍멍이)과 로마자 표기는 이 방식으로 복원되지 않는다. LLM 판정에 맡긴다.
- 겹모음을 나눠 쓴 것(ㄱㅗㅏ→과), 키릴 문자 등 다른 문자로 바꿔 쓴 것, 결합 점이 붙은 라틴 문자(İ)는 복원하지 않는다. 필요하면 혼동 문자 사전을 P1로 추가한다(R5).
- 완성 음절 뒤에 받침을 따로 쓴 것("주ㄱ고")은 의도적으로 합치지 않는다. 합치면 "야ㅅㅂ" 같은 초성 약어가 깨진다.
- 로마 숫자·한자 숫자 끼움("시Ⅰ발" → "시i발", "시一발")은 남는다. 라틴 문자를 보존하는 설계 때문이며, 혼동 문자 사전(P1)에서 다룬다.
- 골격 뷰는 완성 음절 뒤에 그 음절과 같은 모음을 늘여 쓴 것("시ㅣ발", "자ㅏㅏ살")을 지운다. 정규화본은 학생 표현을 그대로 LLM에 보내기 위해 지우지 않는다.

### Risks
- 골격 뷰 어휘 사전이 정상 단어에 오매칭될 수 있다. 수식·코드가 섞인 정상 문장 ≥200건 회귀 세트로 막는다(GR-01).
