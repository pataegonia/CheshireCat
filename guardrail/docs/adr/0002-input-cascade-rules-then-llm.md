# ADR-0002: 입력 판정: 규칙 → LLM, 학습 분류기는 P2

**Date**: 2026-10-30
**Status**: proposed
**Deciders**: danielcho02
**PRD**: GR-04 (이전 초안의 GR-03 분류기)

## Context

조사(R6)에서 1차 선별 모델로 KURE-v1 임베딩 + LogisticRegression과 Neyman-Pearson 보정을 제안했다. 하지만 이 방식에는 세 가지 문제가 있다.
- 임베딩 분류기는 처음 보는 공격 유형에서 AUC가 8–16%p 떨어지고, 놓친 공격에도 높은 확신을 준다.
- 학습·보정 데이터(정상 3,000·공격 2,000건 이상)를 모으는 데 1인 4주 일정의 상당 부분이 든다.
- 보정에 쓸 공개 데이터(KoSBi, K-HATERS)는 학생 질문과 분포가 달라서, "정상 오차단 1%" 보장이 실제 사용자에게는 성립하지 않는다.

학생 발화는 형식이 일정하지 않은 자유 텍스트다. 규칙은 형식이 고정된 패턴(PII, 카나리아, 확실한 탈옥 문구)에만 맞는다. 의도를 판단하는 일은 LLM이 해야 한다(regex-vs-llm 판단 기준).

## Decision

기본 경로는 튜터 PRD 원안인 **규칙 → LLM 정책 판정**이다. 규칙은 확실한 패턴만 차단하고, 의심스러운 패턴에는 플래그만 붙인다. 학습형 1차 분류기는 P2로 둔다. 한국어 우회 세트에서 LLM 판정이 부족하다는 측정 결과가 나오거나 비용·지연이 목표를 넘을 때만 다시 검토한다.

## Alternatives Considered

### 임베딩 분류기 + Neyman-Pearson 보정 (R6 원안)
- **Pros**: 대부분의 요청에서 LLM 호출을 건너뛴다. 오차단에 통계적 보장을 붙일 수 있다.
- **Cons**: 데이터 수집과 학습 비용이 크다. 분포가 다른 데이터로 보정하면 보장이 무의미하다. 심사 환경의 CPU와 가중치 동봉 가능 여부를 아직 모른다.
- **Why not**: 점수에 직결되는 출력 가드보다 시간이 더 든다. council 네 목소리가 모두 P2로 내리자고 했다.

### 소형 가드 모델 (Qwen3Guard-0.6B)
- **Pros**: 한국어 F1이 77–84다.
- **Cons**: CPU 지연을 실측하지 않았고 가중치를 동봉할 수 있는지도 모른다. 학생 범주(S1·S5·S12)가 모델 분류 체계와 다르다.
- **Why not**: 우리 범주 체계를 그대로 쓸 수 없다. 비교 실험은 P2(GR-16)에서 한다.

### 규칙만
- **Pros**: 비용 0, 지연 0.
- **Cons**: 역할극, 위장, 바꿔 말하기를 잡지 못한다.
- **Why not**: 위장·탈옥 범주의 차단율 목표를 맞출 수 없다.

## Consequences

### Positive
- 학습 데이터 없이 GP2 안에 끝난다. 범주를 바꿀 때는 정책 프롬프트만 고치면 된다.
- 튜터 PRD와 구조가 같아서 팀이 이해하기 쉽다.

### Negative
- 거의 모든 입력이 LLM 판정을 한 번 거친다. 요청당 비용이 늘고 RPM 한도에 닿기 쉽다. 지연은 ADR-0007의 병렬 구조로 생성 시간 뒤에 숨긴다.
- "정상 오차단 ≤1% 보장"을 보고서에 쓸 수 없다.

### Risks
- 엘리스 API의 RPM이 낮으면 평가가 돌지 않는다. GR-15 예산 상한으로 막고, 판정 결과는 정확히 같은 입력에 한해 캐시한다.
- 정책 프롬프트(400–600토큰)는 매 호출 반복된다. API가 프롬프트 캐싱을 지원하면 켠다.
