# ADR-0008: 입력 단계 역할 분담 — Jev는 탈옥·인젝션 고신뢰 차단, LLM은 정책 판단

**Date**: 2026-10-30
**Status**: proposed (v2: "판정 백엔드 선택지"에서 "역할 분담"으로 바꿈)
**Deciders**: danielcho02
**PRD**: GR-02, GR-04, GR-05, GR-14, §11, §12

## Context

입력 판정에는 성격이 다른 일이 섞여 있다.
- **탈옥·인젝션 탐지**: 맥락 없이 메시지만 보고 정할 수 있고, 빠르고 안정적인 형식이 중요하다.
- **정책 판단**: 정답만 달라는 요청인지, 수업 밖 주제인지, 위기 하위 분류(T1–T3), 전환·부분 응답 지시. 대화 맥락과 우리 정책 문구가 필요하다.

TypeSafe AI의 Jev는 글을 생성하지 않는 판정 모델이다. 보기 중 하나를 고르고 확률을 돌려준다. 회사 주장 지연은 70–500ms다. 조사([R11](../research/R11-role-split-and-output-latency.md) §1)로 확인한 것은 다음과 같다.
- 경쟁사 측정에서 "이전 지시 무시" 문구가 있는 공격은 99.8%를 잡지만, 돌려 말한 공격은 63.4%, 인코딩 공격은 76%만 잡는다. p95는 526ms였다.
- 주로 영어로 학습됐고, 미국 서버에서 처리한다. Vercel AI Gateway에서는 요청별 무보존을 설정할 수 있다.
- 한국어 성능과 독립 벤치마크는 없다.

v1(같은 날짜)은 Jev를 LLM 입력 판정의 **대체품**(`judge_backend: llm | jev`)으로 두었다. 그러면 Jev가 약한 돌려 말한 공격과 정책 판단을 Jev 혼자 맡게 된다.

## Decision

입력 단계에서 **Jev와 LLM 입력 판정을 둘 다, 생성과 함께 병렬로** 돌리고 역할을 나눈다.

| | Jev | LLM 입력 판정(⑤) |
|---|---|---|
| 맡는 일 | 탈옥·인젝션 여부 하나 (Noul 또는 2지선다) | 범주 S0–S14, 대응 5단계, 위기 하위 분류, 전환 지시 |
| 입력 | 정규화·PII 마스킹을 마친 현재 메시지만 | 현재 메시지 + 최근 턴 요약 + R |
| 차단 권한 | 확률 ≥ τ_J 일 때만 | 고신뢰 차단 |
| 중간 구간 | τ_m ≤ p < τ_J: 차단하지 않고 턴 위험 s_t에 반영 → R이 오르면 다음 턴 문맥이 넓어짐 | — |

- **결합 규칙**: Jev ≥ τ_J 이면 차단한다. 그 외에는 ⑤의 판정을 따른다. 둘 중 하나라도 막으면 막는 OR 결합과 둘 다 막아야 막는 AND 결합은 쓰지 않는다.
- 위기 플래그가 있으면 Jev가 막아도 위기 템플릿으로 응답한다(ADR-0003).
- **τ_J**: 한국어 정상 학생 질문 ≥300건에서 오탐 ≤0.5%가 되는 값으로 정하고, 별도 정상 세트로 확인한다. τ_m은 개발 세트에서 정한다. 홀드아웃에서는 바꾸지 않는다.
- **실패 시**: Jev가 실패하면 ⑤만으로 진행한다. ⑤가 실패하면 Jev가 고신뢰일 때 차단하고, 아니면 허용으로 진행한다. ⑧ 교환 판정이 유해·유출을 다시 본다(ADR-0007, GR-14).
- **켜는 조건**(하나라도 빠지면 `jev: off`, 기능은 ⑤ 단독으로 그대로 돈다):
  1. 주최측이 엘리스 외 외부 API 사용을 허용한다(리더를 통해 확인).
  2. 개발 세트 100건 이상(돌려 말한 공격·인코딩 공격 포함)에서 "⑤ 단독"보다 "역할 분담"의 차단율이 높고 과잉 거절이 늘지 않는다.
  3. 실제 학생 정보가 든 데이터는 보내지 않는다. 대화 기록도 보내지 않는다(REQ-20, 개인정보 국외 이전).
  4. API 키는 환경변수로만 다룬다.
- 근거 판정(⑧)에는 쓰지 않는다. 인용문을 돌려주지 않고(ADR-0005), 근거 판정 벤치마크가 없다.

## Alternatives Considered

### Jev를 LLM 입력 판정의 대체품으로 (v1)
- **Pros**: 호출이 하나 줄고, 형식이 안정적이다.
- **Cons**: Jev가 약한 돌려 말한 공격(63.4%)과 정책 판단을 혼자 맡는다. 위기 하위 분류를 보기로 억지로 합성해야 한다.
- **Why not**: 역할 분담이 같은 지연(병렬)으로 두 약점을 피한다.

### OR 결합 (둘 중 하나라도 막으면 차단)
- **Pros**: 미탐이 가장 적다.
- **Cons**: 오탐이 쌓인다(1 − Π(1 − FPR_i)). Jev는 무해한 이상한 서식에도 반응한다는 측정이 있다.
- **Why not**: 과잉 거절 ≤5%를 지키기 어렵다.

### Jev 결과를 같은 턴의 LLM 판정 맥락에 넣기 (직렬 캐스케이드)
- **Pros**: CC++처럼 1단 신호를 2단이 본다.
- **Cons**: Jev가 끝날 때까지 ⑤를 기다려야 해서 직렬이 된다.
- **Why not**: ⑤는 생성 뒤에 숨어 있어 지연 문제는 없지만, Jev 실패가 ⑤를 막는 의존이 생긴다. 중간 구간 신호는 R을 통해 다음 턴에 반영하는 것으로 충분하다.

### 한국어 오픈 분류기(Kanana Safeguard-Prompt 2.1B)를 같은 자리에
- **Pros**: 한국어 자체 측정 F1 0.844, 정밀도 0.968, Apache-2.0, 외부 전송 없음.
- **Cons**: 자체 호스팅이 필요하다(1인 3주). 회사 자체 측정뿐이다.
- **Why not**: P2. Jev가 조건을 못 채우거나 대기 명단에 막히면 같은 자리에 넣는 대체 후보로 둔다.

## Consequences

### Positive
- 노골적인 탈옥은 빠르고 확실하게 막고, 돌려 말한 공격과 정책 판단은 LLM이 맡는다.
- 둘이 서로 백업이 되어, 판정 실패가 곧바로 안전 응답(과잉 거절)이 되는 경우가 준다.
- "⑤ 단독 / Jev 단독 / 역할 분담" 비교가 보고서 실험 하나가 된다.

### Negative
- 요청당 외부 호출이 1개 늘고(Jev), 동시 호출이 3개가 된다.
- 임계값이 둘(τ_J, τ_m) 늘어 보정할 정상 데이터가 더 필요하다.
- Jev 경로 테스트에는 모의 응답이 필요하다.

### Risks
- 주최측 불허·승인 지연: `jev: off`로 ⑤ 단독. 기능 영향 없음, 비교 실험만 빠진다.
- 한국어에서 오탐이 많아 τ_J가 너무 높아지면 Jev의 차단 기여가 거의 없어진다. 이 결과도 그대로 보고한다.
