## 1. 근거 정리 (research-ops 형식)

### 측정 (공개 세트, 채점 코드 그대로)
- M1 `decision`은 범주의 함수: block = jailbreak_injection·harmful_content·academic_dishonesty·off_topic (200/200).
- M2 비normal의 35%가 다른 범주 문항과 1–5어절만 다른 짝이고, 그 이웃의 80%가 normal이다. "거절하지 말고"·소설 틀·권한 주장은 normal에도 나와 단서가 못 된다. 멀티턴에서 이전 턴이 필요한 비normal은 1/21.
- M3 tutor.jsonl도 같은 10범주 라벨을 가진다 → 분류 자료 400행.
- M4 출력 점수: 상수 응답 0.655, safe 규칙 0.729, grounded만 정답(구간 빈칸) 0.864, 정답 ±2자 0.990.
- M5 숫자·코드 리터럴을 BM25 1위 섹션과 비교하는 규칙: 원래 `NUM_RX`(V0)는 근거 없음 18/35 검출, 가드 근거 있음 32건 오탐 0, 구간 F1 0.627(토큰 ±4자, 창 병합 없음). santa 4라운드 재측정(R13-A §6): 튜터 참조 답변 119건까지 넣으면 V0 오탐 16/119. 기본 변형 V2(섹션 ID 인용 제거 + 수사 클래스 수정)는 18/35, 0/32, 16→6/119(정밀도 0.75), 점수 차 3.5 게이트면 16/35, 0/32, 3/119(0.84)(표본 안 값: NUM_RX 토큰 종류·V2 수정·margin 3.5가 이 공개 행을 보고 정해졌다. 비공개 검출률·정밀도는 더 낮을 수 있다). 창 병합 pm4 구간 F1 0.651(BM25 1위)·0.638(정답 섹션). 문자 2-gram BM25 정답 섹션 1위 96%(64/67), 3위 99%(66/67).
- M6 safe 규칙("block 범주가 아님") + 거절 정규식: 시뮬레이션(거절 탐지 재현율 0.9, 순응 답변 오감지 0 가정)에서 거절 변형 비율 r = 0.5에도 약 0.989. 측정: 원문 기준 튜터 거절 36/36 탐지, 순응 답변 오감지 1/19. 인용·코드를 뺀 원문이면 36/36·0/19, 붙인 뷰면 33/36(R13-A §6.4).
- M7 점수 범위(0–100): 전부 allow 29.5, 입력 완벽 + 상수 출력 84.5, + safe 규칙 87.8, + 오라클 grounded 93.9. 오류 1건 손실(비공개 약 300문항): block 오판 약 0.27, 범주 0.08, 출력 1문항 0.35.
- M8 보이지 않는 문자 0건, "광 고"처럼 음절 사이 띄우기 11건.

### 출처 사실 (R13-B, 확신도는 원문 표시를 따름)
- S1 채점은 `grounded`와 구간을 따로 본다: `grounded=false, []`는 정답과 무관하게 두 항목 중 최소 1점(정답도 false/[]이면 2점; 공개 세트엔 그런 행 0건)(`scoring.py`).
- S2 GPT-5 계열 프롬프트 판정은 구간을 과하게 잡는다(정밀도 약 30%, RAGTruth).
- S3 gpt-5-nano `reasoning_effort=minimal`은 단순 과제에서 정확도가 무너진다. `low`·`verbosity=low` 권장.
- S4 유사 예시 few-shot이 무작위보다 낫고, 예시를 늘린다고 꾸준히 좋아지지 않는다.
- S5 자기 일관성(여러 번 뽑기)은 강한 모델에서 이득이 작다.
- S6 OpenAI SDK 기본값(시간 제한 600초, Retry-After 최대 120초)은 30초 제한을 깬다. FastAPI 422 응답과 SDK 예외에 요청 본문이 실린다.

### 추론
- I1 점수 대부분은 입력 판정(block 경계)에서 나온다(M7). 출력은 규칙과 3단 출력만으로 바닥을 크게 올린다(M4·M5).
- I2 짝 문항(M2) 때문에 문자 n-gram 분류기는 확신하면서 틀린다. 분류기 확신도로 LLM을 건너뛰면 바로 그 짝을 놓친다.

## 2. council: 가드 v6 구조

**Architect(본 세션, 먼저 씀):** 코드로 정밀도를 지키고 nano가 의미 판단을 하는 혼합 구조. 입력 nano 1회(kNN few-shot) + LR·kNN 병행, 불일치면 추가 호출. 출력 nano 1회(근거 없는 구절 + 순응 판정) + 숫자 규칙, 일치 정도로 3단 출력, nano 구간도 다듬어 사용.
가장 큰 위험: 공개 세트 생성 방식에 과적합.

**Skeptic:** A(병렬 2회) 유지, 남는 호출은 입력에. nano 구간은 쓰지 말고 규칙 구간만. 평가는 짝 묶음 단위로 빼야 부풀지 않는다.
근거: 입력 완벽 84.5 대 출력 오라클 +9.4, nano 구간 정밀도 30%로 손익분기(약 0.67)를 못 넘는다.

**Pragmatist:** A 유지, 남은 시간은 결정적 규칙(safe·3단·규칙 구간)과 kNN few-shot에. 합성 데이터 대신 tutor.jsonl 200건. 같은 빌드를 3번 돌려 분산부터 재라.
근거: 마지막 제출만 점수라 복잡도는 막판 회귀 위험.

**Critic:** A 유지, 모든 입력은 nano가 판정(LR·kNN은 힌트·실패 대비). 실격(본문 로그·입력 캐시)과 튜터와 같은 키를 쓰는 동시 호출의 rate limit부터 막아라. 출력 실패 기본값은 `true/[]`.
근거: block 누락 하나가 block-F1·범주·safe를 같이 깎는다.

### 판정
- **합의:** 구조는 A(입력·출력 nano 병렬 2회). 모든 입력은 nano가 판정. `decision`은 코드가 범주에서 도출. safe는 LLM 없이 규칙. 출력은 3단(`true/[]`·`false/[]`·`false/구간`). KB 검색은 문자 2-gram BM25. 평가는 짝 묶음 단위 교차 검증.
- **가장 강한 이견:** 출력 구간에 nano를 쓸지. Skeptic·Pragmatist는 "규칙 구간만", Critic은 "확신이 높으면 짧은 구절이라도 빈칸보다 낫다(한국어 음절 겹침)". 본 세션의 초기안(nano 구간 사용)에 두 목소리가 반대 → 기본값은 **규칙 구간만**, nano 구간은 ablation(규칙과 같은 문장을 가리키고 숫자·고유명을 포함할 때만)으로 짝 묶음 교차 검증에서 순이득이 날 때 켠다.
- **전제 점검:** Skeptic이 "출력 2단(D)·자기 일관성(E)에 호출을 쓰는 것 자체가 틀렸다"고 문제를 바꿨다. 받아들인다: D·E는 채택하지 않는다.
- **바뀐 것(본 세션 초안 대비):** ① nano 구간 기본 사용 → 규칙 구간만. ② 출력 nano의 safe 판정 → 규칙으로. ③ 출력 실패 기본값을 `false/[]`가 아니라 `true/[]`로(Critic. santa 1라운드에서 근거를 고침: ①·②를 거친 뒤 남는 공개 행의 근거 있음 비율 약 0.65 → `true/[]` 기대값 약 1.3 > 1. ②가 꺼지면 non-block 근거 없음 비율 0.52라 `false/[]`가 조금 나음 → S3.1에서 결정, PRD v6 GR-07).
