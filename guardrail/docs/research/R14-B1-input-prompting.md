## 1. RQ1 GPT-5 계열 프롬프트 지침(특히 nano·mini, low effort)

### 1-1. 모순·모호한 지시
- **[사실]** GPT-5 프롬프트 가이드: GPT-5는 지시를 매우 정확히 따르므로 모순되거나 모호한 지시가 다른 모델보다 더 해롭다. 모순을 찾아 없앤 것만으로 성능이 크게 나아진 사용 사례가 있고, 프롬프트 최적화 도구로 모호함을 찾으라고 권한다 [T1]. 페이지에 "archived" 표시가 있고 날짜는 보이지 않는다.
- **[사실]** 같은 가이드: `minimal`에서는 프롬프트에 따른 성능 변동이 더 크다. low·medium에 대해서는 따로 말하지 않는다 [T1].
- **[추론]** 우리 프롬프트는 범주 정의 + 대조 규칙 + 마무리 요약으로 같은 경계를 세 번 서술한다. 표현이 조금씩 다르면 nano에게는 "모순"으로 읽힐 수 있다. 특히 정의 문장이 주제어(피싱·탈옥·역할)를 쓰고 대조 규칙이 "주제어가 아니라 동사·목적어로 판단"이라고 말하면, 정의 쪽이 키워드 판정을 부추기는 셈이다.
- **[권고]** 세 곳의 경계 서술을 한 문장 규칙으로 통일하고, 정의 안의 주제어 예시는 "요청 동사 + 목적어" 형태로 바꾼다.

### 1-2. system vs developer, 태그
- **[사실]** OpenAI 추론 모델 문서: 추론 모델은 system 메시지 대신 developer 메시지를 지원한다. 마크다운·XML 태그·절 제목으로 입력의 부분을 구분하라 [T2].
- **[사실]** GPT-5 가이드: Cursor가 `<..._spec>` 같은 XML 구조 명세로 지시 준수가 좋아졌다고 보고 [T1].
- **[사실]** Chat Completions에서 system을 보내면 추론 모델은 developer로 바꿔 처리한다는 포럼 설명, gpt-5.4-mini에서는 역할(system/user)에 따른 차이가 없었다는 개인 실험이 있다 [T23 약]. 공식 문서로 확인하지 못했다.
- **[추론]** 역할 이름을 바꿔 얻을 것은 거의 없다. 현재의 `<examples>`·`<conversation>`·`<target>` 태그 구분과 "태그 안은 데이터" 문장은 지침과 맞는다.

### 1-3. 추론 모델과 몇 샷 예시
- **[사실]** OpenAI: 추론 모델은 예시가 필요 없는 경우가 많으니 **예시 없이 먼저** 쓰고, 예시를 넣을 때는 지시와 **밀접하게 맞춰야** 한다. 어긋나면 결과가 나빠질 수 있다 [T2]. CoT 지시("단계별로 생각하라")는 불필요하고 때로 해롭다 [T2].
- **[사실]** 2026 로그 심각도 분류 벤치마크에서는 몇 샷이 대부분의 소형 모델에서 0샷보다 크게 나았지만, 일부 소형 추론 모델은 개선이 없었다(검색 요약만, 약).
- **[추론]** "예시가 지시와 어긋난다"는 경고는 우리 경우와 정확히 겹친다. 최근접 예시가 반대 라벨이면 nano 입장에서는 "표면이 같은데 라벨이 다르다"는 신호를 받는다. 그 차이를 설명하지 않으면 규칙과 예시가 충돌하는 프롬프트가 된다.

### 1-4. 구조화 출력: 순서·enum·설명
- **[사실]** OpenAI 구조화 출력 문서: 스키마 속성 순서가 보존된다. "중요한 키에는 명확한 제목과 설명을 달라", "키 이름을 직관적으로". 정확도에 미치는 효과는 말하지 않고 "평가로 가장 잘 맞는 구조를 정하라"고만 한다 [T3].
- **[사실]** "Structure Tax"(AACL 2026): 근거 먼저 배치는 자유 형식과 같거나 낫고, 답 먼저는 큰 하락, 작은 모델에서 더 크다. 근거 먼저 스키마가 보정도 개선 [T5, 초록만, 모델·과제 미확인].
- **[사실]** pydantic-evals 소규모 실험: GPT 모델들에서 필드 순서 차이가 미미 [T6 약].
- **[사실]** 라벨 이름에 설명을 붙이면 0샷 분류가 좋아짐(Mistral-7B, Banking77 81.6 → 88.8) [T24, 검색 요약만]. 다중턴 의도 분류에서 장황한 라벨을 단순화해 +5.09% 보고(AAAI-26, 검색 요약만, 약).
- **[추론]** 순서는 이미 근거 먼저라 바꿀 이유가 없다. enum 값에 붙는 `description`은 스키마 토큰으로 들어가 시스템 프롬프트의 범주 정의와 중복되므로, 넣는다면 정의와 **글자 그대로 같은 한 줄**로 두어 모순을 만들지 않는다.

## 2. RQ2 분해·계층·코드 유도

### 2-1. 속성·체크리스트 필드를 라벨 앞에
- **[사실]** 분류 과제에서 "예/아니오 하위 질문 체크리스트 → 최종 라벨"을 직접 라벨과 통제 비교한 연구는 **찾지 못했다**.
- **[사실]** 위험 편향 평가 벤치마크(2026-09): 상위 모델의 하위 질문 단위 일관성 98.88%인데, 하위 답에서 결정 지도로 이어지는 **종단 일관성은 45.13%**, 일부 오픈 모델은 0% 가까이. 저자는 "오류 누적 효과"라 부른다 [T20, 초록만].
- **[추론]** [T20]은 "모델이 하위 질문은 잘 답해도 그것을 최종 판정으로 잘 잇지 못한다"는 증거다. 이것은 **최종 라벨을 코드로 유도**하는 쪽(§2-3)에 유리한 근거이고, 같은 호출 안에서 속성을 쓰고 라벨을 모델이 다시 고르게 하는 방식에는 불리하다.

### 2-2. 계층(이진 먼저 → 하위 유형) vs 평면 N지선다
- **[사실]** 상품 분류 연구: 계층형 프롬프트가 평면과 같거나 못했고 몇 샷보다 나빴다. 1단계 오류가 2단계로 전파되기 때문. 예외로 한 모델은 각 단계 선택지가 적어 macro 지표가 나았다 [T19, 검색 요약만].
- **[사실]** 선택지 수가 늘수록 정확도가 떨어진다(60지 32.5% vs 2지 94.3%, gpt-3.5 0샷) [T7]. 안전 분야에서는 "가벼운 이진 필터 → 강한 모델의 세부 분류" 2단 시스템이 있지만 같은 모델·같은 데이터의 2단 vs 1단 비교는 찾지 못했다.
- **[추론]** 우리 점수는 block F1이 지배하므로 "1단계 = 채점되는 결정"이다. 오류 전파 걱정은 2단계(범주 정확도, 가중 0.10)에만 해당한다. 그러나 별도 호출로 나누면 지연이 늘고, 같은 호출에서 `block` 불리언을 범주 앞에 두는 방식은 근거가 없다. 

### 2-3. 추출한 속성에서 코드로 라벨 유도
- **[사실]** 영상 판독 라벨링: 규칙 먼저, 규칙이 실패한 칸만 LLM으로 보내는 혼합이 LLM 단독보다 정확하고 자원도 적게 씀(규칙 단독 F1 0.81 → 혼합 0.99), 다만 정형 보고서라 규칙에 유리했다고 저자가 밝힘(검색 요약만, 약).
- **[사실]** 데이터 품질 주석 비교: LLM 주석의 이득은 과제 의존적이고, 단순 기준선이 LLM과 거의 같았던 과제도 있음(검색 요약만, 약).
- **[추론]** 우리 최소쌍은 "같은 주제어 + 다른 요청 동사·목적어"라서, 모델이 **요청 행위**(만들어 달라/분석·설명해 달라/역할을 바꿔라/역할 지정 프롬프트를 검토해 달라)와 **목적어 성격**(실행 가능한 유해 산출물인가)을 따로 뽑게 하고 block 여부를 코드가 정하면, 표면 유사도가 아닌 경계 변수에 모델의 주의를 고정하는 효과가 있을 수 있다. 근거는 간접적이다.

## 3. RQ3 대조·최소쌍 몇 샷

### 3-1. 복사 효과와 최근 편향
- **[사실]** Z-ICL(ACL 2023): 시험 입력과 같은 입력의 예시가 있으면 모델은 그 예시의 라벨을 맞을 때 90% 이상, **틀릴 때도 70% 이상** 따라간다. 예시가 시험 입력에 가까울수록 예시 라벨의 정오가 더 중요해진다 [T10]. 1차 출처 대조: Table 2에서 맞는 라벨 90.8/94.2%, 틀린 라벨 73.9/81.7%(GPT-J/GPT-NeoX, CR 데이터셋, channel 방식). 2021–2022년의 비추론 모델 수치다.
- **[사실]** 2025 ICLR 기제 연구: 모델이 질의와 비슷한 예시의 라벨 표현을 찾아 질의 표현으로 복사하는 회로를 보고(검색 요약만, 약).
- **[사실]** 규칙 추론 과제에서 **잘못된 규칙을 담은 예시 하나**가 성능을 크게 떨어뜨렸다. 중간층에는 맞는 규칙과 틀린 규칙이 함께 표현되고 위치 주의 편향을 보이는 머리가 있다 [T12, 2026-03, 초록만].
- **[추론]** 우리 반대 라벨 최근접 예시는 "틀린 라벨"이 아니라 **맞는 라벨이 붙은 다른 문장**이다. 그러나 모델이 차이(1–5단어)를 놓치면 사실상 "동일 입력에 반대 라벨"로 보여 [T10]의 70% 복사 쪽으로 간다. 이 효과는 같은 템플릿의 같은 쪽 예시가 최근접일 때는 정답을 돕는다. 즉 **kNN 복사는 양날**이고, 결과는 최근접이 어느 쪽 짝이냐에 달린다. 로컬 측정(block 문항의 절반에서 최근접이 반대 라벨)이 그 위험의 크기다.

### 3-2. 대조 예시를 보여 주는 방법
- **[사실]** 대조 CoT(2023-11): 맞는 풀이와 틀린 풀이를 함께 보여 주면 일반 CoT보다 추론 벤치마크에서 나았다. 대조 예시를 자동 구성하는 방법도 제시 [T9, 초록만, 수치 미확인].
- **[사실]** 대조 ICL(AAAI 2024): 원하는 것(긍정)과 피할 것(부정) 예시를 주고, 답하기 전에 **둘의 차이를 모델이 먼저 정리**하게 하는 방식. 대조 예시 + 지시를 합친 변형이 일반 몇 샷보다 일관되게 나았다. 대조 예시를 짧은 지시로 압축해 길이를 줄일 수도 있다 [T8]. 생성 과제 결과이고 분류가 아니다.
- **[사실]** PC-CoT(ACL Findings 2024): 두 후보 라벨의 **공통점과 차이점을 분석한 뒤 고르게** 하는 프롬프트. 유사점(similarity) 단계를 빼면 62.01 → 52.49, 차이점 단계를 빼면 → 55.71, 둘 다 빼면 52.59(Table 3 평균) [T7]. 유사점 단계를 뺄 때의 하락이 더 크다(1차 출처 대조에서 초안의 두 값이 뒤바뀐 것을 고침, [verification.md](verification.md) §R14).
- **[사실]** 예시에 설명을 붙이면 다듬지 않은 설명으로도 이득이 있고(예시 추가 효과의 약 1/3, 과제 지시의 약 2배), 소형 검증 세트로 다듬은 설명은 이득이 훨씬 크다. 단 **큰 모델에서만** 이득이 났다 [T11, 2022].
- **[사실]** 라벨별로 묶기 vs 섞기, 쌍으로 묶기의 직접 비교는 **찾지 못했다**. 순서 효과는 다중 클래스에서 크다 [S29].
- **[추론]** 근거들은 한 방향이다: 최소쌍은 **쌍으로, 차이를 명시해서** 보여 주는 것이 단독 예시를 나열하는 것보다 낫다. 차이 설명은 nano 같은 소형 모델에서 이득이 작을 수 있으므로[T11] 길게 쓰지 말고 "차이: 요청 동사 '작성해' vs '분석해'" 같은 한 줄로 둔다.

## 4. RQ4 logprobs 없는 불확실성 신호

### 4-1. 2순위 라벨(runner-up)
- **[사실]** 분류에서 2순위 라벨을 함께 묻는 방식의 효과를 잰 연구는 **찾지 못했다**.
- **[추론]** 2순위 라벨은 그 자체로 확률이 아니지만 "어느 두 범주 사이에서 헷갈렸나"를 알려 주므로, §4-4의 2지 판정 호출에 넣을 후보 쌍을 정하는 데 쓸 수 있다. 신호로서의 신뢰도는 측정해야 한다.

### 4-2. 말로 낸 확신
- **[사실]** Qwen3-32B는 SST-2에서 확신 값이 8종뿐이고 절반 이상이 95%. 4개 데이터셋·2개 모델에서 같은 양상. 해법(숫자 토큰 확률로 가중)은 logprobs가 필요하다 [T13, Findings ACL 2026].
- **[사실]** 9개 LLM × 영어 이진 분류 3종: 말로 낸 확신은 순위(PR-AUC 0.80)는 괜찮지만 서로 다른 값이 평균 9개, 45%가 최빈값. 여러 번 묻기는 해상도를 높이고 약한 모델에 도움이 되지만 **정확도 90% 이상 모델에서는 해칠 수 있다**. 소수점 자리를 더 달라고 하면 잡음만 늘었다. 권고: 정확도 85% 미만이면 여러 번 묻기, 90% 이상이면 말로 낸 확신으로 충분 [T14, 2026-06, 요약 페이지로 확인].
- **[사실]** 소형 LM 라우팅 연구: 확신의 변별력이 모델마다 크게 다르고(최고 AUROC 0.857), 최악은 거의 한 값으로 몰림(검색 요약만, 약).
- **[추론]** nano의 block 결정 정확도가 85–90% 부근이면 [T14]의 경계에 있다. 확신 필드 하나를 문턱으로 쓰는 설계는 해상도가 부족할 가능성이 크다. R13-B §2-4의 "신호 일치(kNN·LR·LLM)" 방식이 이 근거와 맞는다.

### 4-3. 불일치 시에만 2번째 호출
- **[사실]** MoT 캐스케이드(ICLR 2024): 약한 모델 여러 표의 일치도를 문턱과 비교해 어려운 문항만 강한 모델로 보냄. 강한 모델 단독과 비슷한 정확도에 비용 약 40%. 외부 검증기(LLM·RoBERTa)는 같은 비용에서 일치도 방식보다 못했다 [T15].
- **[추론]** 우리는 강한 모델이 없으므로 "강한 단계"는 **다른 형식의 nano 호출**(2지 대조 판정)이어야 한다. 같은 프롬프트로 다시 묻는 것은 R13-B §2-5대로 이득이 작다.

### 4-4. 2지 대조 판정 vs N지 재질문
- **[사실]** 2지 선택이 가장 정확하고(94.3%), 후보를 좁힌 뒤 2지 대조(PC-CoT)가 N지 0샷·몇 샷·CoT·자기 일관성보다 나았다. 자기 일관성(FS-CoT, 약 24호출)은 +0.19점, 후보 축소+PC-CoT(약 12호출)는 +8.74점 [T7].
- **[추론]** 우리 쓰임에서는 후보 축소가 필요 없다. 첫 호출의 범주 + 2순위(또는 kNN·LR이 가리킨 반대 결정 범주)로 쌍이 정해진다. 따라서 추가 비용은 **불일치 문항에 1호출**이다. 대조 대상이 block 범주 vs 가장 가까운 allow 범주(예: harmful vs normal-분석 요청, jailbreak vs 프롬프트 검토 요청)라는 점이 최소쌍 구조와 정확히 맞는다.

## 5. RQ8 지시 언어

- **[사실]** KMMLU-Redux/Pro(2025-07) §6.4 표 3: o4-mini 영어/한국어 프롬프트 75.80/76.17, 69.65/69.10. Grok-3-mini·Qwen3 추론 모델들도 ±2% 안쪽. Llama-4-Scout은 한국어 프롬프트에서 −33.3%·−50.6%(형식을 무시함). 저자 결론: 프롬프트 언어가 행동을 바꿀 수 있고, 닫힌 모델은 거의 영향이 없었다 [T16]. 객관식 지식 시험이지 분류가 아니다.
- **[사실]** 비영어 감정 분류(NLI 기반 0샷)에서 영어 프롬프트가 목표 언어 프롬프트와 같거나 나았다(2024) [T17, 검색 요약만]. 그러나 이전 비교는 목표 언어 지시·데이터가 영어에서 기계 번역된 경우가 많아 영어에 유리했다는 반론과, 번역하지 않은 자료로 다시 잰 연구가 있다(NAACL 2025 short) [T18, 결과 수치 미확인].
- **[사실]** gpt-4o-mini의 한국어 코드 생성: 영어 설명 예시가 한국어 예시보다 약간 나음(73.6 vs 75–78.7) (검색 요약만, 약). gpt-4o-mini·gpt-5-mini·nano의 **한국어 분류에서 지시 언어를 바꾼 측정은 찾지 못했다**.
- **[추론]** GPT 계열 닫힌 추론 모델은 지시 언어에 둔감하다는 쪽이 가장 가까운 근거다[T16]. 우리 경계는 한국어 요청 동사의 미세한 차이에 있으므로, 정의를 영어로 바꾸면 한국어 동사 예시를 영어로 옮기며 경계가 흐려질 위험이 오히려 크다. 우선순위가 낮다.

## 6. RQ10 gpt-5-nano·mini effort별 새 측정

- **[사실]** LiveBench 일반 과제(질문 세트 2026-01-08): gpt-5-nano low 34.3, high 48.6(일반 에이전트 적합도 28.3 vs 43.4). medium은 표에 없음. 분류 과제 아님 [T21 약].
- **[사실]** 보험 서류 분류(영어, 2025-12 업계 보고서): nano minimal 70.0%, 나머지 설정은 대체로 80% 초중반이라는 검색 요약만 있다. PDF를 열었으나 본문을 읽지 못해 **표를 확인하지 못했다** [T22 약, 미검증].
- **[사실]** 그 밖의 effort 비교는 R13-B의 [S18][S19][S22]와 같은 출처를 다시 찾은 것뿐이다.
- **[추론]** R13-B §4-3의 결론("minimal은 무너진다, low부터 정상, medium 대비 low 손실은 쉬운 과제에서 작다")을 바꿀 새 근거는 없다. 어려운 일반 과제에서는 low→high 차이가 크다[T21]는 점은, **불일치 문항에만 effort를 올리는** 선택지가 생각해 볼 만하다는 정도의 신호다. 단 effort를 바꾸면 캐시 접두가 달라진다[S15].

## 7. 우리 설계에 주는 시사점

### 7-1. 실험할 가치가 있는 변형 (우선순위 순)

| # | 변형 | 이유·근거 | 비용 |
|---|---|---|---|
| 1 | **쌍 단위 예시**: 각 kNN 예시에 그 예시의 반대 결정 최근접 짝을 붙여 "A(라벨) / B(라벨) — 차이: 요청 동사·목적어 한 줄"로 제시. 단독 "가장 비슷한 것을 마지막" 배치를 없앰 | 복사 효과·최근 편향을 상쇄하고 경계 변수를 명시 [T10][S25][T7][T8]. 프롬프트 길이 증가는 쌍 수를 3–4로 줄여 상쇄 | 오프라인 짝 표 1회 + 프롬프트 변경 |
| 2 | **순서 절제 실험**: 최근접 마지막 / 처음 / 라벨 무관 무작위 / k=0 | 현재 배치가 오답을 끄는지 직접 측정. block 문항 중 "최근접이 반대 라벨"인 부분집합에서 따로 본다 | 프롬프트 변경만 |
| 3 | **불일치 시 2지 대조 판정 호출**: LLM·kNN·LR 결정이 엇갈리거나 2순위가 반대 결정이면, 두 후보 범주의 정의·쌍 예시를 주고 "공통점 → 차이 → 선택" | 2지가 가장 정확하고, 유사점·차이점 분석 둘 다 기여한다(빼면 각각 −9.5, −6.3) [T7]. 일치도 기반 선택 호출 [T15] | 불일치 문항만 +1호출 |
| 4 | **요청 행위 속성 필드 + 코드 유도**: `request_act`(산출 요청/분석·설명/역할 변경/검토 등 enum), `target_artifact_harmful`(bool) 등을 범주 앞에 두고 block은 코드 규칙과 모델 범주를 비교 | 모델은 하위 판단은 잘해도 최종 연결에서 틀림 [T20]. 근거는 간접 | 스키마·규칙 작성 |
| 5 | **프롬프트 모순 점검**: 정의·대조 규칙·마무리 요약의 경계 서술을 하나로, 정의 안 주제어 예시를 동사+목적어 형태로, 얼버무림 표현 제거, 범주 충돌 시 우선순위 명시 | GPT-5는 모순에 민감 [T1], 얼버무림은 오탐 유발·우선순위 명시 [T4] | 작음 |
| 6 | **2순위 라벨 필드**: 3번의 트리거·후보 쌍 결정용으로만 | 직접 근거 없음. 비용이 작아 시험할 만함 | 스키마 필드 1개 |

### 7-2. 우선순위가 낮거나 하지 않을 것

- **영어 지시로 교체**: GPT 닫힌 추론 모델은 지시 언어 차이 1% 안쪽[T16]. 한국어 동사 경계를 영어로 옮기는 손실 위험이 더 크다. 시간이 남을 때만.
- **말로 낸 확신(0–100) 필드를 문턱으로**: 값이 몇 개로 몰려 문턱 해상도가 없다[T13][T14]. 신호 일치 방식이 낫다.
- **별도 호출 2단 계층(이진 → 범주)**: 지연 증가, 평면보다 나빴다는 보고[T19]. block F1은 1단계에서 결정되므로 범주 정확도(가중 0.10)를 위해 호출을 늘릴 이유가 약하다.
- **같은 프롬프트로 여러 번 묻기(투표)**: R13-B §2-5대로 강한 모델에서 이득이 작고, [T7]에서도 +0.19점.
- **예시마다 긴 설명**: 소형 모델에서 이득이 작다[T11]. 쌍의 차이 한 줄로 충분.
- **developer/system 역할 바꾸기**: 기대 효과 없음[T2][T23 약].
- **effort medium 전면 적용**: 새 근거 없음, nano는 medium에서 지연 악화[S18]. 불일치 문항에만 올리는 실험은 3번과 비교할 후보로만.

### 7-3. 측정할 때 주의 [추론]
- 1·2번은 "최근접이 반대 라벨인 block 문항" 부분집합과 "최근접이 같은 라벨인 문항" 부분집합으로 나눠 본다. 쌍 제시가 앞쪽을 고치면서 뒤쪽(복사가 정답을 돕던 경우)을 망칠 수 있다.
- kNN 풀 평가는 R13-B §2-2의 leave-intent-out을 유지한다. 비공개 세트는 같은 템플릿의 다른 변형이므로, 같은 템플릿의 짝이 풀에 있는 상황 자체는 실제 조건과 같다.

## 8. 찾지 못한 것

- gpt-5-nano·gpt-5-mini에 대한 **분류 과제의 몇 샷 vs 0샷**, 예시 순서, 필드 순서 측정.
- **최소쌍(1–5단어 차이로 라벨이 뒤집히는) 예시를 넣었을 때** 분류 성능의 직접 측정. 대조 예시 연구는 생성·수학 추론이 대부분이다.
- 예시를 **라벨별로 묶기 vs 섞기 vs 쌍으로 묶기**의 직접 비교.
- 분류에서 **2순위 라벨**을 묻는 방식의 신뢰도.
- gpt-4o-mini·gpt-5 계열의 **한국어 분류에서 영어 vs 한국어 지시** 비교.
- 체크리스트 하위 질문 → 라벨을 직접 라벨과 비교한 통제 실험(분류).
- gpt-5-nano effort low vs medium의 **분류 정확도** 새 측정(2026). [T22]는 표를 열지 못함.
- 확인하지 못한 수치: 대조 CoT의 벤치마크 수치[T9], Enomoto 등의 결과[T18], "Structure Tax"의 모델·효과 크기[T5], 보험 분류 표[T22], 계층 vs 평면 상품 분류의 수치[T19].
