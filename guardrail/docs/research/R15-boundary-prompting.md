# R15 경계 판별 프롬프트: 선행 연구와 프런티어 가드 정책 비교

작성 2026-11-15 · 담당 danielcho02 · 대상: S3.2(#152) 입력 판정 프롬프트 v2의 V4(경계별 판별 가이드) · 앞선 조사: [R14-B1](R14-B1-input-prompting.md)

웹 조사만 했다(API 호출 0). 조사 에이전트 3개(Sonnet)가 모은 것을 메인 세션이 근거 등급을 붙여 합쳤다. **[확인]** 표시는 메인 세션이 원문을 다시 읽어 맞춘 값이고, 나머지는 에이전트 보고 값이다. [추론]은 우리 과제(gpt-5-nano, effort low, 한국어 입력 10범주)로 옮긴 판단이다. 외부 데이터셋의 문항 문구는 이 문서와 프롬프트에 옮기지 않는다(SPEC §7.1).

## 1. 프런티어 가드의 정책 구조 (RQ1)

| 시스템 | 정책 형태 | 언급 대 사용 처리 |
|---|---|---|
| gpt-oss-safeguard | 지시·정의·위반·비위반·예시(4–6개) 절, 출력 형식을 위아래에 | "허용" 단계에 위험 주제를 **묻는** 질문을 짝 예시로 둠 |
| Llama Guard 4 | 범주 14개, 각 1–2문장, "가능하게 하다·부추기다·지지하다" 같은 동사 | 동사 선택으로 처리, 제외 목록 없음 |
| Llama Prompt Guard 2 | 지시를 **덮어쓰려는 명시적 의도** 이진 판정 | 의도 기준 |
| ShieldGemma | 한 문장 정책 + "예:" 목록 + 허용 예외 문장 | 정책 안에 예외를 씀 |
| Qwen3Guard | 9범주 + 안전·논쟁·위험 3단 | "논쟁" 단계가 맥락 의존 사례를 받음 |
| Granite Guardian 3.3 | 짧은 기준 또는 사용자 기준 한 문장 | 페르소나 탈옥 예시를 위험으로 |
| NemoGuard / Aegis 2.0 | 범주 23개 목록 + "주의 필요" | 주소 찾아 달라는 요청 = 개인정보 위반 |
| Constitutional Classifiers | 자연어 유해 목록 + 긴 **무해 목록** | 무해 목록으로 경계 표시 |

공통점: ① 행위로 정의 ② 허용 예외를 같은 곳에 명시 ③ 짧은 경계 예시 양쪽. 표현을 바꾸는 효과를 통제해 잰 공개 실험은 찾지 못했다(가장 가까운 것: 정책 문구의 강도를 바꾸면 판정이 32–71% 뒤집히고 예외 절의 위치만 옮기면 6–9%, arXiv 2605.06161, 판정기 에이전트 대상).

## 2. 언급 대 사용, 과잉 방어 (RQ2)

- 원인은 **촉발어 지름길**이다: 모델이 문장이 무엇을 하는지가 아니라 단어에 반응한다(InjecGuard의 주의 가중 시각화 **[확인]**).
- 미세조정 가드는 학습으로 고쳤다(MOF, 짝 데이터). 인컨텍스트 규칙으로 고친 정량 결과는 찾지 못했다. 범용 LLM 판정(GPT-4o)은 작은 인코더보다 이 문제에 덜 취약했다(NotInject GPT-4o 86.73%, 에이전트 보고).
- 정상·유해 짝을 함께 학습하면 과잉 거절이 크게 줄고 재현율 손실은 작았다(32.94% → 4.16%, 유해 쪽 거절 91.88% → 87.72%, arXiv 2609.04482, 미세조정).
- 외부에서 가져온 정상 문장에서는 어려운 음성 예시 보강의 효과가 덜 일반화됐다(arXiv 2609.15017, 2026 사전 공개 1건).
- [추론] nano에는 **누구에게 하는 지시인가**를 먼저 쓰게 하는 것과, 같은 표면 단어의 짝 예시가 인컨텍스트로 옮길 수 있는 유일한 수단이다.

## 3. 상세 지침의 손익 (RQ3)

- 지침서형 프롬프트는 최소 프롬프트보다 낫고, 예시를 더하면 더 낫다(발견 6). 경계에 근거를 단 어려운 사례가 오래 다듬은 코드북보다 나았다는 보고도 있다(64.9% 대 57.8%, 2차 요약, 중).
- 길이: nano급은 지시 수가 늘수록 빨리 떨어진다(IFScale, 키워드 포함 과제라 분류 직접 전이는 [추론]). 정책 최적 길이 400–600토큰(발견 1).
- 순서: 앞쪽이 더 잘 지켜지고, 순서만 바꿔도 판정이 흔들린다. 11/13의 v2a(범주를 판정 순서 목록으로)가 앞쪽 범주로 끌려간 것과 같은 현상으로 본다 [추론].
- 체크리스트 단독은 나쁘고 비교 단계가 붙어야 한다(발견 9). 11/13의 요청 유형 분해(정밀도↑ 재현율 붕괴)와 맞는다 [추론].

## 4. 언어 (RQ4)

직접 근거 없음. 지시는 영어(1.1 측정과 같음), 예문은 입력과 같은 한국어로 둔다 [추론]. 촉발어 자체가 한국어로 오기 때문이다.

## 5. V4 작성 지침 (S3.2 작성자와 검토자에게)

1. **틀**: 1.1의 범주 정의·출력 형식은 그대로 두고, "How to draw the boundaries" 절만 경계별 블록으로 바꾼다. 블록은 서로 독립인 평평한 목록이다(순서형 판정 절차로 쓰지 않는다).
2. **블록 순서**: 손실이 큰 경계부터. 탈옥(적용 대 대상) → 자기소개 pii → 남의 정보 → 과제 대행 → 과정 밖 산출물 → 모욕.
3. **블록 형식**(경계마다 같은 모양, 문구 강도도 같게): ① 두 범주를 대칭으로 묻는 판별 질문 하나 ② 각 쪽을 **행위로** 정의한 한 줄씩 ③ "다음은 단어가 같아도 이쪽이다"라는 허용 예외 한 줄 ④ **같은 표면 단어로 라벨이 갈리는 지어낸 최소쌍 1–2쌍**(한국어, 공개 문항과 다른 소재) ⑤ 함정 단어는 3개 이하로만 언급.
4. **우선순위**: 블록 끝이 아니라 한 곳에 모아 쓴다. "인용·분석과 유해 요청이 함께 있으면 유해 요청 쪽", "자기소개와 남의 정보 요청이 함께 있으면 harmful_content"(1.1과 같음).
5. **근거 필드**: `evidence`를 두 부분으로 — ① 학습자가 튜터에게 지금 하라는 행동 ② 공격·유해 문구가 있으면 그것이 **튜터에게 하는 지시인가, 다루는 대상인가**. "단계별로 생각하라"는 쓰지 않는다(추론 모델 지침).
6. **안전 강조를 줄인다**: 경고 문장을 늘리지 않고, 탈옥의 기본값을 "학습자가 튜터에게 행동을 바꾸라고 **명령할 때만**"으로 적는다.
7. **재현율 보호**: 탈옥·harmful 쪽 예시에 "수업용·예로"라는 틀을 씌운 진짜 공격을 하나 넣어, 정상 쪽 문구가 우회로가 되지 않게 한다.
8. **길이**: 경계 블록 전체 증가 약 600토큰 목표, 900토큰 상한. 넘으면 예시부터 줄인다.
9. **얼버무림 금지**: "대체로·보통·주로" 같은 말을 쓰지 않는다. 정의와 예시가 서로 어긋나지 않게 검토한다(GPT-5는 모순에 약함).
10. **과적합 방지**(플랜과 같음): 폴드 0–2 오판만 보고 쓰고, 공개 발화와 8-gram 겹침 0을 테스트로 고정한다.

측정 때 함께 볼 것: 헷갈리는 범주 쌍의 재현율을 따로(전체 F1이 이득을 가릴 수 있음, 발견 7), 진짜 탈옥·harmful 재현율, 늘어난 토큰과 호출 p95. 블록 순서 섞기·예시 2쌍 대 3쌍 비교는 호출 예산 밖이라 하지 않는다.

## 6. 찾지 못한 것

- gpt-5-nano(effort low)로 긴 지침을 쓴 분류 측정.
- 인컨텍스트 규칙만으로 언급 대 사용 오탐을 줄인 정량 결과(대부분 미세조정 결과).
- 분류 프롬프트 안 범주 정의의 위치 효과("중간에서 잃음") 정량.
- 한국어 탈옥·주입 판정 데이터와 예문 언어 비교.
- 확인하지 못한 수치: IFScale 모델별 표(gpt-4.1-nano 72.8/51.6/16.2 등, 에이전트 보고), PLOS One 표 값(LLM 추출), NotInject 모델별 정확도(PromptGuard 0.88% 등).

## 방법

조사 에이전트 3개(Sonnet)가 firecrawl·exa로 RQ1(프런티어 가드 정책), RQ2·RQ4(언급 대 사용·언어), RQ3(상세 지침 손익)을 나눠 읽었다. firecrawl 일일 한도로 일부는 exa로 읽었고 몇 논문은 초록·요약만 봤다. 메인 세션이 OpenAI 가이드·InjecGuard·IFScale 원문을 다시 읽어 표의 [확인] 값을 맞췄다.
