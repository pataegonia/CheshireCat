## 판정

채택 기준은 미리 정한 대로다: 후보의 3회 범위가 기준의 범위와 겹치지 않고 높다(닿으면 겹침). 비교 지표는 가드 점수.

| 질문 | 판정 | 근거 |
|---|---|---|
| default가 nano 단독보다 높은가(C2 관문) | **통과, 다만 0.30점 차이** | 79.89 대 79.59. block 판정 한 행이 약 0.3–0.4점이라 한 행에 걸린 결과다 |
| `max_completion_tokens` 1600 | **채택**(실패율 기준) | 출력 호출 실패 6.2–9.4%(전부 잘림) → 0/192. 2% 기준(R14-D8)을 3회 모두 넘던 것이 없어졌다 |
| `nano_span` 켬 | **가드 점수로는 확인 못 함. 출력 지표로는 나음** | 가드 점수 83.68–84.84가 A와 겹친다. 출력 평균은 0.827–0.837 → 0.889–0.899로 겹치지 않는다. 구간 F1 0.684 → 0.793–0.806 |
| `knn_fewshot` 끔 | **채택 안 함** | block F1 0.805–0.843이 A(0.783–0.876)와 겹치고 범주 정확도는 조금 낮다(겹침) |

- **default의 우위는 전부 출력 쪽에서 나온다.** 출력 평균 +0.10(약 4.6점). block F1은 A와 B가 완전히 겹친다. kNN 예시·kNN 다수·LR이 입력 판정을 nano 단독보다 낫게 한다는 근거는 이 실측에 없다.
- **조합의 이득(+약 2.8점)도 전부 출력 쪽이다.** 가드 점수에서 출력 항을 뺀 값은 조합 43.2–44.8, default 42.7–47.2로 겹친다.
- 조합에서 `nano_span`과 토큰 상한이 둘 다 출력에 작용해 둘의 몫을 가를 수 없다. 구간 F1이 오른 것은 `nano_span`, 실패가 없어진 것은 토큰 상한으로 읽는 것이 자연스럽지만, ③에 닿는 행 수도 10–11 → 12–16으로 늘어 일부는 경로가 바뀐 효과일 수 있다.
- **입력 few-shot의 앞선 결과는 재현되지 않았다.** 입력 단독 실측에서 "예시 없음 0.809–0.854 대 v1 0.771–0.805"로 0.004 차이로 안 겹친다고 적었는데, 이번에 예시가 있는 default가 0.876까지 나왔다. 그때의 차이는 잡음 안이었다고 본다.

## 잡음

| 항목 | 값 |
|---|---|
| 같은 설정 안의 가드 점수 폭 | A 4.75점, B 3.91점, C 1.16점 |
| 같은 설정 안의 block F1 폭 | A 0.093, B 0.074, C 0.038 |

| 출력 평균 폭 | 약 0.01 |

- 가드 160행 × 3회로는 입력 쪽 차이가 block F1 약 0.08(10행쯤) 이상이어야 가려진다. 지금 시험한 입력 변경은 모두 그보다 작다.
- 출력 평균은 폭이 0.01이라 0.02쯤의 차이도 가려진다.

## 결론과 다음

- `max_completion_tokens`를 1600으로 올린다(문서 먼저 → `default.yaml`).
- `knn_fewshot`은 그대로 켠다.
- `nano_span`은 가드 점수 규칙으로는 못 채웠지만 출력 지표가 분명히 낫다. 조합의 몫을 가를 수 없는 경우라 결정을 사용자에게 올린다. 가르려면 출력 단독(1600, `nano_span` 켬 대 끔, 3회씩, 약 390회 호출)이면 된다.
- 내리면 안 되는 결론: 보조 판정기가 입력을 낫게 한다, few-shot이 좋다/나쁘다, 조합의 +2.8점이 어느 한 설정의 것이다, 0.30점 차이의 관문 통과가 튼튼하다.
- 홀드아웃은 아직 열지 않았다(0/3회 사용).
