작성 2026-11-14 · 담당 danielcho02 · 결정: [R14-D9](../docs/research/R14-prompt-uplift.md)

**결론: 영어판(1.1)이 R14-D9 채택 기준을 넘었다. 입력·출력 판정의 기본 프롬프트를 영어판으로 바꾼다.** 이 실험에서 시도한 변형 수: 1(영어판 하나).

## 실행

- 런박스, 같은 코드(브랜치 `gr/v1-english`, main `c929a8f` 위)로 실행했다.
- 기본 설정(교차 검증 320행, 홀드아웃 열지 않음)에서 한국어 v1과 영어판을 1회씩 번갈아 3묶음 돌렸다.
- 영어판은 `--set prompts.input_judge=input_judge_en.md --set prompts.output_judge=output_judge_en.md --set prompts.output_judge_baseline=output_judge_baseline_en.md`로 골랐다.
- 실행마다 판정 호출은 375회(입력 311 + 출력 64)이고 probe 5회가 붙는다. 6회 합계는 2,280회다.
- 실측 전 요청 1회로 키 상태를 봤고 HTTP 200이었다.
- 6회 모두 무효가 아니었고(`invalid` 없음), 역할별 호출 실패는 0건이었다.
- 설정 해시: 한국어 `cba7a73b69…`, 영어 `464e634818…`.

## 판정 (R14-D9 기준)

- 가드 점수·범주 정확도·출력 평균에서 영어 범위가 한국어 범위 전체보다 아래가 아니다. 통과.
- block F1 최솟값: 영어 0.810, 한국어 0.776. 영어가 높으니 통과.
- 짝 문항 block 정확도 최솟값: 영어 0.868, 한국어 0.849. 영어가 높으니 통과.
- 범위가 겹치지 않은 것은 출력 평균(영어가 위)과 지연 p95(영어가 짧음)다. 나머지 지표는 범위가 겹친다. master-plan §10의 "분산 밖 개선"은 출력 평균에서만 보였고, 가드 점수 차이는 분산 안이다.

## 읽는 법과 한계

- 한국어 v1이 회차마다 81.93–87.59로 5.7점 흔들렸다. 이전 유효 6회(82.76–85.71)보다 넓다. 그사이 코드(S2.8–S2.10 머지)가 바뀌어 이전 범위와 직접 비교하지 않는다.
- 영어판 block F1과 짝 문항 정확도의 최댓값은 한국어보다 낮다(0.867 대 0.879, 0.906 대 0.943). 기준은 최솟값으로 정했으므로 통과지만, block 경계에서 영어판이 확실히 낫다고 말할 근거는 없다.
- 출력 판정이 오른 이유와 지연이 준 이유는 재지 않았다. 지연은 프롬프트 토큰이 줄어서일 수 있다(추정).
- 베이스라인(`configs/baseline.yaml`, nano 단독)은 영어로 다시 재지 않았다. 베이스라인은 한국어 그대로 둔다.
- 측정 순서는 R14-D9의 "S3.2 먼저"와 달리, 사용자 결정으로 영어판을 먼저 쟀다.
