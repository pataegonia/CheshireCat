# S3.2 입력 판정 프롬프트 v2(경계별 판별 가이드): 선별 5회 · 확정 6회

**결론: 경계별 판별 가이드(V4)가 #152 채택 기준을 넘었다. 영어 입력 프롬프트를 1.1에서 2.0으로 바꾼다.** 이 실험에서 시도한 변형 수: 3(V4, V1 예시 없음, V4+V1). 계획했지만 돌리지 않은 변형: V2(근거 두 단계만), V3(정의 세 줄만), C2(#154 `mode` 필드) — V4가 통과해 조건부 실행 조건이 생기지 않았다. C3(#154 모순 문장 수정)는 V4가 대체했다.

## 실행

- 런박스, `guardrail.eval.run --input-only`(입력 판정만, 출력은 상수), 교차 검증 320행(가드 160 + 튜터 160), 홀드아웃 열지 않음, 동시 16. 코드 `gr/s3.2-v4-guide` `e05ef35`.
- 비교는 가드 160행. 표의 "가드 점수"는 출력이 상수인 값이라 절대값은 의미가 없고 같은 조건끼리 차이만 본다.
- 판정 호출: 실행당 입력 판정 311회(하네스 추정치는 325회) × 11회 = 3,421회(V4 선별은 `--repeat 2`라 622회) + 실행마다 probe 5회. 실패 0, `finish_reason=length` 0%.
- V4 작성: 폴드 0–2의 오판 28행만 보고 썼다(폴드 3–4는 측정 전 읽지 않음). 예문은 지어낸 한국어이고 공개 발화와 8-gram 겹침 0(테스트로 고정). Opus 적대 검토 1회(높음 2·중간 4·낮음 3)를 반영한 뒤 문구를 고정하고 쟀다.

## 읽는 법과 한계

- **이득은 놓친 공격이 준 데서 온다**(재현율 0.77–0.88 → 0.88–0.93)와 범주 정확도(+약 0.07)다. 겨냥한 첫 오류인 normal→탈옥 오탐은 줄지 않았다(7–9행). 경계 가이드가 탈옥 블록보다 harmful·과제 대행·자기소개 블록에서 더 효과를 냈다고 읽는다 [추론].
- 1.1 r3(0.776)이 낮아 범위가 벌어졌다. 이전 11/14 1.1 3회(0.810–0.867)와 비교하면 V4 범위(0.848–0.886, 선별 포함)는 겹친다. 채택은 같은 날 번갈아 잰 비교로만 판정했다(R14-D9와 같은 방식).
- 입력 호출 p95가 약 0.9초 늘었다(프롬프트 약 900토큰 증가). 요청 p95는 입력·출력 병렬 중 느린 쪽이고, 11/15 혼합 부하 가드 p95 5.15초라 여유가 있다. 배포 뒤 다시 잰다.
- 출력 판정과 함께 돈 가드 점수는 재지 않았다(출력 쪽은 바뀌지 않음). 실제 영향은 다음 제출로 본다.
- 베이스라인 설정(`configs/baseline.yaml`)은 "기본과 같은 입력 프롬프트에서 예시만 뺀다"는 불변식으로 같은 프롬프트를 쓴다. 베이스라인 수치는 다음 베이스라인 실측에서 다시 잰다.
- 원본: 런박스 `~/s32/guardrail/runs/s32-*`, `s32c-*`(커밋하지 않음). 비교 도구는 `scripts/r14/error_breakdown.py`와 `scripts/r14/screen_compare.py`(행 단위 고침·새로 틀림·폴드 분리).
