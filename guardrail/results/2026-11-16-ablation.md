# S3.6 ablation 표 — 설정 6.0.6 기준 1차 (2026-11-16)

부품을 하나씩 끄고 가드 점수를 쟀다. **3회 범위로는 끄면 점수가 오르는 부품이 보이지 않는다. 이 표로는 설정을 바꾸지 않는다.**

- **1차 표다.** 설정 6.0.6(입력 프롬프트 2.0, 출력 프롬프트 1.1) 기준이다. 동결 후보의 프롬프트가 바뀌면 이 표를 재사용하지 않고 모든 행을 다시 잰다(C3-tuning S3.6). 점수를 받치는 부품 넷이 모두 출력 쪽이라 출력 프롬프트가 바뀌면 크기가 달라질 수 있다.
- **지연 표는 아직 수용 기준을 채우지 못한다.** 3절의 지연은 어느 실행 값인지 확인하지 않았다. S3.6은 이 문서로 닫지 않는다.

- 코드 `42837b3`(main), 설정 6.0.6, 런박스 한 곳에서 한 번에 실행했다.
- 대상은 교차 검증 개발 분할의 가드 160행(후보 답변 64행)이다. 홀드아웃은 열지 않았다.
- 설정 10개 × 3회, 예상 20,165호출. 진짜 Guard 경로다(`--input-only` 아님).
- 명령: `uv run python -m guardrail.eval.run --config configs/default.yaml --name s36-abl --ablation configs/ablation --only no_knn_fewshot,no_knn_vote,no_literal_rule,no_low_signal_direct,no_lr,no_nano_span,no_nano_tier3,no_safe_rule --repeat 3 --max-calls 22000`
- `with_embedding`·`with_oom_kb_snippet`·`with_third_call`은 미구현이라 뺐다(켜면 기동 실패).

## 2. 읽는 법

- **출력 쪽 부품 넷이 점수를 받친다.** nano ③단계(약 −6점), safe 규칙(약 −4.5점), nano 구간(약 −3점), 숫자·리터럴 규칙(약 −2점)은 끄면 범위가 default 밖으로 떨어진다.
- **입력 쪽 부품 넷은 차이가 보이지 않는다.** kNN 예시·kNN 다수결·LR·저신호 직접 판정은 범위가 default와 겹친다. "꺼도 된다"가 아니라 "3회로는 구별할 수 없다"는 뜻이다.
  - 범위 위쪽 끝이 default보다 높은 것은 no_knn_vote 하나(92.62 대 92.41, 0.2점)다. 같은 설정의 실행 폭(약 1.5–3.7점)보다 훨씬 작다.
  - no_knn_fewshot은 3회 폭이 3.7점으로 가장 넓고, 재현율(0.86–0.88)과 범주 정확도(0.75–0.78)가 default 범위 아래다. 예시는 그대로 둔다.
  - kNN 다수결과 LR은 nano가 실패했을 때의 기본값으로만 쓰인다(`guard.py`). 이 실행에서 입력 판정 오류는 설정당 0–3건이라 차이가 날 자리가 거의 없었다.
- default의 90.96–92.41은 같은 날 A/B의 category 3회(90.28–90.76, `2026-11-16-input-flags.md`)보다 높다. 같은 설정·같은 코드라 실행 묶음 사이의 흔들림으로 본다.

## 4. 하지 않은 것

- 보고서의 "default 대비 행별 점수 평균 차이" 절은 옮기지 못했다(런박스 터미널을 다른 작업과 같이 쓰는 중이었다). 원본은 런박스 `~/s36/guardrail/runs/s36-abl/`에 있다.
- 3회로는 1–2점 차이를 가르지 못한다. 겹침으로 나온 네 부품을 끄려면 같은 날 번갈아 3회 대 3회로 다시 재야 한다.
- 제출로 확인하지 않았다.
- 남은 일(S3.6을 닫으려면): 동결 후보 설정으로 모든 행을 다시 재고, 지연은 회별 값으로 표를 만든다. default의 p95가 긴 이유(순서·혼잡)도 그때 가린다.
- 3절 요약 줄에서 no_knn_fewshot·no_knn_vote·no_low_signal_direct의 출력 평균이 default보다 높게 적혀 있다. 어느 실행 값인지 모르는 줄이라 1절 범위와 견줄 수 없고, 결론의 근거로 쓰지 않는다.
