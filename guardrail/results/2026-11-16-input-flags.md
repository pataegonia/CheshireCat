# S3.8 입력 판정: 범주 앞 예/아니오 두 칸 (flags 모드) — 2026-11-16, 미채택

입력 판정의 JSON 출력에 범주보다 먼저 두 칸을 쓰게 했다.
- `makes_offcourse_output`: 수업과 무관한 산출물을 튜터가 만들게 되나.
- `makes_work_to_submit`: 평가에 낼 완성 과제를 튜터가 만들게 되나.

**결론: 기본값으로 쓰지 않는다(설정 6.0.6, `label_mode: category` 그대로).** flags는 실험 변형으로 코드에 남긴다(`input.label_mode: flags`, 기본 끔).

- 프롬프트는 `input_judge_en_flags.md`(version `2.2-flags`)다. 2.0에 "해롭지 않음 ≠ normal" 문단 하나, 지어낸 예시 하나, 두 칸 정의를 더했다.
- 처음에는 칸이 참이면 코드가 허용 범주를 차단 범주로 올리는 규칙도 두었다. 모든 실행에서 한 번도 작동하지 않았고, ADR-0012(입력 판정은 범주만 쓴다)·R14-D5(속성에서 차단을 도출하지 않는다)와 충돌해서 뺐다. 지금 flags 모드는 칸을 판정에 쓰지 않는다.
- 측정은 모두 교차 검증 개발 가드 160행에서 했다. 홀드아웃은 열지 않았다.

## 왜 시도했나

- 통합 보고서(11/16)는 가드가 차단을 놓치는 유형으로 긴 글이나 수업 틀로 감싼 과제 대행·주제 밖 요청을 꼽았다.
- 놓친 행을 보면 nano는 evidence에 요청을 맞게 적고도 "해롭지 않다"며 normal을 냈다. 읽기는 맞는데 범주로 옮기는 단계에서 틀렸다.
- 입력 프롬프트 2.1("해롭지 않음 ≠ normal" 문단만 추가)은 선별 1회에서 F1 0.897로 기준선 범위 안이었다. 그래서 칸을 더한 flags로 넘어갔다.

## 결과 1: 입력 단독 실행 (`--input-only`) — 이득처럼 보였다

| flags 선별 r1 | 0.920 | 4 | 3 | 0.791 |
| flags r2 / r3 / r4 | 0.943 / 0.932 / 0.941 | 3 / 4 / 2 | 2 / 2 / 3 | 0.836 / 0.821 / 0.806 |

범위가 겹치지 않아 처음에는 채택했다(기본값 전환 커밋 `0f5bc1d`). 하지만 다른 날 기록과 비교했고, 전체 경로가 아니었다.

## 결과 2: 진짜 Guard 경로 A/B — 이득 없음

같은 날(11/16) 런박스 한 곳(`0f5bc1d`)에서 번갈아 전체 실행했다. 실행마다 약 709호출, 실패는 0이었다.

|---|---|---|---|---|---|
| B category(2.0) | 90.76 / 90.72 / 90.28 | **90.59** | 0.918 / 0.916 / 0.899 | 0.836 / 0.791 / 0.806 | 0.914 / 0.925 / 0.928 |
| A flags(2.2-flags) | 88.21 / 90.80 / 89.56 | 89.52 | 0.884 / 0.907 / 0.876 | 0.776 / 0.806 / 0.806 | 0.904 / 0.932 / 0.935 |
| C 칸만(2.0 + 두 칸 정의, 문단 없음) | 89.06 / 89.28 / 92.21 | 90.18 | 0.884 / 0.918 / 0.953 | 0.791 / 0.791 / 0.821 | 0.920 / 0.891 / 0.913 |

- 실행 전에 정한 규칙(평균 +1.0점 이상이면 바꾼다)으로는 A(−1.07)와 C(−0.41) 모두 미달이다.
- 지연 p95는 세 변형 모두 6.2–6.8초로 차이가 없었다.
- C 프롬프트는 저장소에 넣지 않았다. 만드는 법: `input_judge_en_flags.md`에서 "Harmless is not normal" 문단을 2.0의 "Judge a pasted text…" 한 줄로 되돌리고 예시 줄을 지운다.

## 결과 3: 실제 제출 A/B — 차이 없음

런박스에 A(포트 8001)와 B(8002)를 함께 띄우고 `submission.json` 주소만 바꿔 번갈아 제출했다. 비공개 세트이고, 제출마다 문항 표본이 바뀐다.

| 순서 | A1 | B1 | A2 | B2 | A3 | B3 |
|---|---|---|---|---|---|---|
| 가드 | 89.73 | 90.70 | 88.95 | 90.01 | 90.20 | 87.89 |
| 총점 | 85.12 | 85.63 | 84.39 | 85.63 | 85.08 | 83.73 |

가드 평균은 A 89.63, B 89.53이다(+0.10). 시간 초과·형식 오류·판정 오류는 6회 모두 0이었다.

## 왜 이득이 안 보였나

- **고칠 수 있는 몫이 작다.** 감싼 요청 놓침은 개발 차단 43행 중 약 5행이다. 다 고쳐도 가드 +1–1.5점이다. 같은 설정 실행 사이의 폭은 약 2–3점이다.
- **프롬프트를 바꾸면 다른 행이 흔들린다.** A의 가장 나쁜 실행(88.21)에서 새로 틀린 행은 정상→탈옥 오탐, harmful→pii, answer_seeking→academic_dishonesty 등으로 고르게 흩어졌다. 출력 프롬프트 1.2·1.3에서 본 현상과 같다.
- **입력 오답은 출력 점수도 깎는다.** 입력 범주가 차단이면 출력이 `safe=false`가 된다(`decide.safe_of`). 그래서 입력 단독 F1만 보고 가드 점수를 어림하면 틀린다.
- 입력 단독과 전체 경로가 왜 다르게 나왔는지는 확인하지 못했다. 두 경로가 nano에 보내는 메시지를 비교하는 스크립트는 런박스 브라우저 조작 승인 문제로 돌리지 못했다. 코드상 차이는 이전 발화를 2000자로 자르는지뿐이다.

## 교훈

- 입력 단독 1–4회와 다른 날 기록의 비교로는 채택하지 않는다. 같은 날 전체 경로를 번갈아 3회 대 3회 돌려 판단한다.
- 리뷰(PR #203, 통합) 지적의 처리:
  - 올리기 규칙: 삭제했다.
  - flags 모드에서 탈옥 2차가 study면 칸이 버려지는 점: 칸을 판정에 쓰지 않으니 해당 없다.
  - 프롬프트 문장의 범위: 측정한 그대로 두어 기록과 맞춘다. 기본값이 아니라 고치지 않았다.
  - 스키마 docstring: 중립 문장으로 바꿨다(모델에 description으로 간다).
  - 튜터 행 범주 기록: 기본값이 그대로라 필요 없다.
