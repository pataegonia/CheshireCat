# 후보 D: 근거 불일치 답변만 한 번 고쳐 쓰기 (2026-11-18 밤~11-19, yang-co1)

`2026-11-18-oom-candidates.md` 5절에서 보류한 후보 D를 실제로 구현해 쟀다.

**결론: 보류.**
- 공개 개발에서는 작게 오른다(튜터 +0.10·+0.26).
- 공개 밖 팀 45문항에서는 0 근처라 이득이 확인되지 않았다.
- 코드는 기본 끔 토글로 둔다. 실제 제출로는 재지 않았다.

## 1. 왜 다시 봤나: 요청당 4회는 대회 규정이 아니다

- 5절에서 D를 보류한 이유는 요청당 nano 4회(TU-13)였다. 이것은 튜터 PRD의 팀 규칙이다.
- 대회 규정(SPEC §3, OT "API 사용과 어뷰징"·"자주 묻는 질문")은 이렇다.
  - API 호출 한도는 따로 없고, 너무 과한 호출만 어뷰징으로 볼 수 있다.
  - 요청당 30초 제한이 있다.
  - 전체 채점 시간 한도는 공개되지 않았다(베이스라인 약 2분, 5분에서 끊김).
- 그래서 일부 요청에 1회를 더하는 D를 실험했다. 이 토글을 켜면 해당 요청은 TU-13의 4회를 넘을 수 있다.

## 2. 동작 (`toggles.repair`)

| 값 | 동작 |
|---|---|
| `off` | 지금과 같다(**기본, 동결 설정 값**) |
| `top1_mismatch` | `cite_top1`이 모델 인용에 없던 검색 1위 섹션을 더한 최종 answer만 nano 1회로 고쳐 쓴다 |

- 재시도는 없다. 호출 상한은 10초이고, 요청 마감까지 4초 미만이면 부르지 않는다.
- **입력:** 초안이 인용한 섹션, 더한 1위 섹션(`추가="예"`), 초안 문장·근거, 대화. 프롬프트는 `tutor/prompts/repair.md`이고 공개 세트와 15자 겹침이 0이다.
- **받는 조건(하나라도 어기면 초안 답을 그대로 낸다):**
  - 같은 스키마(`MainCallOut`)이고 범주·action이 초안과 같다.
  - claim 문장마다 인용 문구 하나 이상이 섹션 원문에 실제로 있다.
  - 결정적 수정(IN-04)을 거친 뒤에도 answer이고, 인용이 있고, 빈 답 안내가 없다.
- 고정 문장, answer가 아닌 응답, 모델이 이미 1위를 인용한 답에는 부르지 않는다.
- 테스트 `tests/tutor/test_repair.py`(18개)가 확인하는 것:
  - 끔 / 켬
  - 실패·범주 변경·action 변경·잘림·빈 답에서 초안 유지
  - 원문에 없는 인용 문구 거부
  - 시간 부족이면 부르지 않음
  - 재시도 0

참고(이 PR과 별개): 기존 결정적 수정(IN-04)은 인용 문구가 섹션 원문에 있는지 보지 않는다. 테스트를 쓰다 확인했다. 재작성 경로에만 원문 대조를 넣었다.

## 3. 측정

**조건**
- 같은 답에서 재작성 전/후를 공식 채점(`score_one`)으로 팔당 3회 판정했다(8병렬, 판정 오류 0).
- 측정한 코드는 main `f38ab31` + #240(`oom_schedule`)이다. #239(`quote_from_top1`)·#241 병합 전이다.
- 개발 PC, 운영진 gpt-5-nano, 동시 8. 본문은 메모리에만 두었다.

| 판 | 세트 | 시도 / 교체 / 시간 초과 | 재작성 소요 p50 | 튜터 환산(재작성 − 초안) |
|---|---|---|---|---|
| v1: 근거 묶음 전체 + 더한 섹션, 8초 | 공개 개발 160, 생성 2회 | 10/0/10 · 15/5/8 | 8.0 · 7.6초 | 0 · **+0.57** |
| v2: 초안 인용 섹션 + 더한 섹션, 10초 | 공개 개발 160, 생성 2회 | 15/8/5 · 15/8/3 | 5.5 · 6.9초 | **+0.10 · +0.26** |
| v2 | 팀 45, 생성 3회 | 8/6/1 · 7/6/1 · 6/5/0 | 6.0 · 6.5 · 8.4초 | **−0.37 · +0.62 · −0.25**(45문항 기준) |

**공개 개발 v2**
- 문항 11개(행 id로 묶음) 평균 +0.049점/문항, 부트스트랩 95% [+0.004, +0.102].
- 이득은 대부분 인용 F1이다. 고쳐 쓴 답이 정답 섹션만 인용해 0.67 → 1.0이 된다.
- 나빠진 경우는 1회 1문항(자료 밖, −0.17)이다.

**팀 45**
- 사실 라벨이 없어 인용·충실만 본다.
- 인용이 오른 행 4개, 충실이 떨어진 행 4개가 섞였다. 문항 8개 평균 −0.005 [−0.042, +0.028].

**비용**
- 재작성이 붙는 요청은 공개 개발 160의 약 9%다. 그 요청은 5~10초 늘어난다.
- 동시 64 실서버에서는 시간 초과가 더 늘 것으로 본다(미측정).

**무효로 처리한 실행 1번**
- v2 첫 실행은 도중에 개발 PC가 절전에 들어가 연결이 끊겼다(판정 URLError 72, 튜터 연결 오류 104).
- 판정에 쓰지 않았고, 다시 돌렸다.

**운영진 API 호출:** 약 2,600회(튜터 2,119, 판정 456). 무효 실행 1번이 포함된다.
