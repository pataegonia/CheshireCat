## 3. 제출 판의 실효 구성과 요청 흐름

| 항목 | 값 |
|---|---|
| 요청 예산 | 24초(+ 안전망 3초, 상한 29초) |
| 주 호출 | `main` 18초, 겹쳐 보내기 12초, 재시도 1회, reasoning low, 출력 상한 2000 |
| T 의도 판정 | serial, 8초 |

| 영어 장치 | 켬 |

| 실패 기본값 | `fallback_quote`, `delegation_override` 켬 |
| 가드 단계 | `guard_classify` off, `verify` off. 가드는 6.0.10 |
| 요청당 nano | 정상 3회(T + 주 호출 + E), 최악 5회(+ 재시도 + 겹쳐 보내기). 임베딩은 따로 센다 |

요청 하나의 흐름(`tutor/judge/flow.py`):

1. **대화 정리와 결정적 신호.** 빈 발화나 자모·기호뿐인 발화는 LLM 없이 고정 clarify로 답한다.
2. **직렬 T.** 8초 안에 오면 이름표로 정한다.
   - refuse·위기 고정 문장이면 주 호출 없이 끝낸다.
   - redirect·scaffold 고정 문장은 주 호출 결과와 맞춰 정한다.
3. **E 시작.** KB에 없는 이름 붙은 말이 있거나 영어 발화일 때만 부른다. 주 호출과 병렬로 돈다.
4. **검색과 주 호출.** 상위 5개 섹션을 근거로 한다(영어는 임베딩 순위).
   - 12초가 지나도 안 끝나면 겹쳐 보낸다.
   - 실패하면 자료 인용 답이나 고정 문장을 낸다.
5. **덮기와 인용.** 대행 보정 → T 덮기 → 규칙 A 인용 1위 더하기 → 후처리.
6. **마무리.** 최종 answer인데 E가 "근거에 없음"이면 자료 밖 고정 문장(abstain)으로 바꾼다. 아니면 인용 1위 섹션의 자료 문장을 덧붙인다.
